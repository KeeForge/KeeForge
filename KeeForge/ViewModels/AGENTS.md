# ViewModels

**Scope:** `@MainActor @Observable` app state and UI-independent workflow owners. Use Foundation/Observation, never SwiftUI (enforced by `ci_scripts/validate_architecture.py`) or AppKit (by convention; the script does not check it). Heavy work goes to services or detached tasks; only the result is published here.

## Ownership

Name the owner before changing a workflow. Views render, collect input, and forward lifecycle events; they never repeat the policy owned below. Add a coordinator only for a distinct responsibility, composing `DatabaseViewModel` operations rather than bypassing them.

- `DatabaseViewModel`: one database session. Authoritative for unlock/lock, save/conflict/merge, rekey, re-encryption, the authentication grace period (`secretAccess`), and the derived search/tag/AutoFill-exclusion indexes.
- Cloud conflict-copy creation tries a numbered name after a proven no-commit conflict, rechecking session and reference authority before every attempt; uncertain outcomes never trigger another attempt.
- `DatabaseOpeningSteps`: the steps an opening screen lists (sync, decrypt, open) and their states, for every platform's opening view. `UnlockKeyFileSelection`: an unlock form's key-file read, off the main actor, dropping a result a newer pick or cancel replaced.
- `DatabaseSessionStore`, owned by `KeeForgeApp` on iOS and `AppDelegate` on Mac, retains sessions until retirement completes their transition lock; a deferred retirement must be retried, and active selection is always explicit. Forced retirement discards unsaved work and clears secrets when the app drops a session unconditionally.
- App activation, background/system lock, iOS inactivity resets, and live Settings effects fan out through `DatabaseSessionStore` to every stored session, regardless of active selection. Database-list removal force-retires every missing session. Targeted inactivity resets affect only the session with the supplied database ID. Mac activity uses that targeted API; Mac activation evaluates existing deadlines without renewing them.
- `DatabaseWorkspaceState` (`DatabaseViewModel.workspace`): selection, typed `DatabaseRoute` navigation, the open iOS editor with its coordinator, search activation, menu request counters. No tree or secret data, no navigation objects or view references.
- `MacSidebarModel.swift`: the Mac sidebar's AppKit-free model. `MacSidebarSnapshot` decides its sections and rows (the Recycle Bin section and when it is left out included), and `MacSidebarGroupActions` which group-row menu actions are offered. Group-row menus read `MacSidebarGroupActions` instead of repeating its gates. `MacEntryDrop` owns dragging entries onto sidebar groups: the private pasteboard payload (entry, database and window UUIDs only) and the drop decision, which performs through `PendingMove`; the sidebar and list controllers only translate AppKit calls.
- `MacDatabaseSettingsModel`: Mac per-database tabs, file facts/backups keyed on the session's open-time hash, non-secret master-key summaries, and reference writes. Session-owned edits route through the session; AutoFill participation always uses `DatabaseListViewModel.setAutoFillEnabled` with its refresh bridge. Launcher settings hold no session or destination group. KDBX 3.1 and hardware-key read-only modes remain fixed in both contexts. `MacDatabaseSettingsModelTests` covers these contracts; `DatabaseViewModelTests` covers composition after typed unlock/rekey and its clearing on lock.
- `MacDatabaseStatus`: the Mac status card (name, storage and state line, its one recovery action, which buttons apply) and the notices above the entry list, one state at a time in the SyncProblems board's precedence. A cached copy the provider refused the saved sign-in for (`cloudSyncNeedsReconnect`) shows as disconnected, with Reconnect, which syncs again once it connects. Pending AutoFill upload counts come from the database list through `MacWorkspacePresentation.pendingUploads`; it never carries a secret.
- `MacEntrySelectionSummary.swift`: what the Mac detail column shows for a multiple selection (count, names, shared group, whether Move and Delete apply).
- `MacEntryListModel.swift`: the Mac entry list's AppKit-free model. `MacEntryListSnapshot` decides the mode (search, tag, collection, group), rows, glyphs (the SSH badge from attachment names alone, never key bytes), the header's title and count line, the footer hint and empty state with its New Entry offer, leaving usernames unresolved for the cell; `MacEntryListSelection` maps the table's selection onto `selectedEntryID` and `entrySelection`; `MacVerificationCodeClock` holds only the displayed code per time step and drops it on a lock-cycle or content change.
- `MacIconPickerModel`: Mac entry/group icon selection, valid-change gating and cancellable favicon state. Group purpose offers standard icons only; the AppKit adapter filters undecodable custom images and clears the model on end.
- `MacCopyFeedback`: which entry and field a Mac window last copied (list, menu bar and detail fields alike), for 1.5 seconds, never the value. It is set only through `recording`, after the guarded copy path has written the clipboard; `MacWorkspacePresentation` owns one per window.
- `MacEntryDetailModel.swift`: what the Mac detail shows for an `EntrySource` (the live entry or one stored version): `MacEntryField` rows in board order, header and footer facts, attachment sizes, tags with their inherited sources, and `MacEntryFormatting` for text that is not a field value. Its reveal, copy and Large Type actions go through `DatabaseCommands`; it stores reveal flags, never plaintext, and decrypts a revealed field only while on screen. `MacWorkspacePresentation.detailModel(for:in:currentSession:)` keeps one per window for the selected entry.
- `AttachmentPreviewSession`: a Mac window's attachment Quick Look and Share, one per window over `AttachmentPreviewFileStore`. It writes a plaintext copy only for an explicit preview or share, holds one at a time, rechecks the window's session, lock cycle, selected entry and the attachment itself after the load and before writing, and removes the file when the preview ends, the share of that same file finishes or fails, `reconcile()` finds the request stale (lock, another entry or session, attachment changed) or the window closes. A quit that goes ahead removes every preview (`MacWindowCoordinator`); the session's `clear(owner:)` and the launch purge stay as backstops.
- `MacEntryHistorySession`: one open Mac History sheet: the versions, the selected one as `MacEntryDetailModel(.history)` with its `EntryVersionComparison`, its own `MacCopyFeedback`, and Restore through `restoreEntryVersion`. It answers only while the lock cycle, content revision and selected entry it opened under hold; `MacWorkspacePresentation` owns at most one per window (`currentEntryHistory(in:)`) and drops it on dismissal, another entry's detail model and `reset()`.
- `PasswordGeneratorModel`: every generator surface's options (persisted through `SettingsService`, one shared set), suggestion, last-character-set rule and strength cap. The suggestion lasts until regenerated or `close()`.
- `LargeTypeModel` and `EntryVersionComparison`: what Large Type shows (numbered, classed tiles; built only inside a disclosure) and which fields of a stored version differ from the current entry. The comparison decrypts protected values only to compare; a difference carries the current value only for an unprotected field whose references stay at the default clearance.
- `MacWorkspaceCommands`: the Mac menu-bar commands that act on a window's presentation as well as its session (Library, Duplicate, Move to Group, Sort, Expand/Collapse All Groups, Sync Now, Database Settings, Import Passwords), gated by the same rules as the row menus and toolbar.
- Import Passwords requires an unlocked, writable, idle, unfrozen workspace with no other window sheet requested: import outranks them and would end a dirty group editor. The launcher's New Database and Connect to Server are dimmed and refused while its sheet is busy creating or connecting. Export copies encrypted bytes and is available even while locked when the targeted database has a readable local copy; it never needs a session key.
- `EntryRowActions`: every entry-row menu gate and effect (copy, duplicate, restore, move, select, delete), read by the SwiftUI row items and the Mac table.
- `MacWorkspacePresentation`: per-window Mac editors (a duplicate from search or a tag selects the copy in place, other created entries are revealed), the inline entry editor's `MacEntryEditorSession` and the editing freeze (`freezesWorkspace`, `openEditor(in:)`), pending row actions, group creation form, expansion and folded sidebar sections, database details, save-error presentation, and reconnect lifetime. Each Mac database window owns its own; the window's `MacWorkspaceSheets` resets it on lock and on window invalidation, except expansion and folded sections, which last for the window's life in memory. It holds no database session. Column focus stays in views; native split widths and collapse state belong to AppKit autosave, and `isSidebarCollapsed` only mirrors the sidebar's for the list header.
- `MacEntryEditorSession`: one open Mac entry editor, holding the form, its `DatabaseEditorCoordinator`, its attachment imports and its reveal flags, so a redraw of the detail column keeps unsaved work and the lock-prompt registration. The presentation (or the enrollment flow through it) activates it on open and deactivates it on every close. While one of its sheets, popovers or alerts is up (`isPresentingChild`) it cannot save, counts as unsaved, and declines a manual lock or window close, so nothing saves or closes it behind the child.
- `DatabaseEditorCoordinator`: editor activation, dirty-editor registration, draft submission, save/delete completion, Save and Lock. `EntryEditViewModel` / `GroupEditViewModel` own only form state, validation, and the payload they emit. The group form also holds the original/pending parent; `updateGroup` stages fields and a validated move atomically before the coordinator saves once.
- `AppSettingsViewModel`: preference persistence and its live effects on open sessions.
- `AppRoutingCoordinator`: single-session launch order, queued database routes, incoming-URL classification, and Open/Close Database transitions. It owns the enrollment coordinator and forwards launch-presentation gating.
- `TOTPEnrollmentCoordinator`: enrollment parsing results, five-minute parked-link expiry, destination database/session binding, deferred presentation and stale sheet callbacks. A bound destination is looked up by database ID, never window focus; replacement or retirement discards the link. Lock/unlock of the same session parks and resumes it with fresh generation checks. On Mac the destination sheet hands the link to the inline editor (`handOffToEditor`); only the editor's save consumes it, and a cancel presents the destinations again. The single-session shell may carry an unassigned link through database selection until appearance; explicit destination selection binds immediately.
- `MacUnlockFormModel`: one Mac database window's unlock form (password, key file, layout per `biometricUnlockAvailability`, field error, focus requests, Locate and Try Again through `MacUnlockFilePicking`, a recovery page's Reconnect), driving the session through `MacUnlockSession`. `MacDatabaseOpenPage` decides which page a locked, opening or failed window shows (form and card, opening steps, recovery page and its actions, the inactivity footer); `MacLockedDatabaseSummary` what that window may say about the database, and the file-and-storage line the Databases window shares.
- `MacDatabasesLauncherViewModel`: the Databases window's decisions: which references and connect providers appear on Mac (local, WebDAV, FTP only), each row's storage line, problem or last-opened line, badges, Open (unlocked window) or locked and Touch ID, the row menu's items and their effects, whether Open opens or fronts (only ever the selected or clicked row), empty and first-run states, the sheet, chooser and confirmation the window presents, the enrollment destination choice, and refusing Remove (asked and again on confirmation) while that database's session has unsaved work or a write in flight (`canRemove`, which a locked window's Remove from List also checks). It holds no session.
- `MacApplicationRouting`: Mac policy, applied by `MacWindowCoordinator`, for launch presentation ordering, queued opens, duplicate fronting, launcher requests and explicit enrollment destination effects. The adapter supplies open database IDs and resolves file URLs to database IDs; this policy owns no windows or restoration.
- `EntrySecretAction`: every reveal/copy disclosure that follows device-owner authentication.
- `DatabaseCommands`: platform-neutral database command enablement, delete-title variant, and actions; presentation and app routing stay in the shell. Its copies take an entry ID; the menu-bar ones pass `commandEntryID`, and the password copy always goes through `copyEntryPassword` (device-owner prompt, `EntrySecretAction.currentSession` and window rechecks). `discloseEntrySecret` is that gate for any protected value; password and field copies, Large Type and the Mac detail's reveals all use it. A plain value copies at once, a stored-protected one, or one whose field references reach a protected value, only through it.
- `DatabaseListViewModel`: the database list and all pending-upload draining (`drainPendingUploadsOnAppActive()`); a session never drains. Every reload delivers the final references through application-installed hooks for missing-session retirement and matching-session reconciliation. Reference edits start from the persisted list, never a stale row snapshot.
- Reference reconciliation only updates existing sessions. The persisted reference takes precedence over a delayed callback snapshot because session saves and syncs write their learned metadata there first. Reconciliation never writes the list, reloads content, or changes lock state; identical references publish nothing.
- Registry reload retains the last confirmed list on read failure; lifecycle consumers must not retire sessions from an unavailable registry projection.

## Invariants

### Lock, unlock, authentication

- Every lock calls `ClipboardService.clearOwnedContents()`. `preservingClipboard` is the single exception and only iOS backgrounding sets it (copy, switch apps, paste). Regression-prone; macOS has no expiring pasteboard, so a missed scrub leaves the secret there.
- `lock()` clears all session state (keys, `sessionKeyFileData`, binary pool, draft, attachment preview files, workspace). Preview writes, dismissal, lock, and reload use this view model's stable `attachmentPreviewOwnerID`, never the persisted database ID; clearing one session must leave other sessions' previews intact. Clear any new session state there too.
- An async session operation captures `lockCycleID` before its first await and publishes nothing in memory if it changed, or session secrets reappear behind the lock screen. Persisted state mirroring a completed write (keychain, reference, upload markers) still updates.
- An unlock attempt sets its outcome only while `finishUnlockAttempt` accepts its `prepareForUnlock()` token, so a late YubiKey answer or slow KDF cannot unlock behind a lock. The token is not `lockCycleID`, which paces biometric auto-unlock once per lock.
- Quick unlock reads the composite key and the express-unlock key in one `BiometricCompositeKeyOperation`. Both unlock paths open through `openForUnlock` and hand the opened version's key to `quickUnlockKeyPersistOperation` with the composite key. Only a typed master key (password unlock, created database) passes `masterKeyEntered`, which restarts the quick-unlock password interval; a rekey restarts it directly. `biometricUnlockAvailability` is `.none` once that interval has run out or no key is stored, and `.unavailableWithStoredKey` while a stored key cannot be released now; `canUseBiometrics` means `.available`. Once it has run out, `unlockWithBiometrics` deletes the items and returns `.passwordFallback` without a prompt. A hardware-key session is opened without `ExpressUnlock` and passes no express key, whatever the Keychain held.
- A save replaces the express-unlock item with the saved version's key (`expressUnlockKeySaveOperation`) only when this session wrote its composite key to the quick-unlock item, at unlock or rekey (`quickUnlockItemHoldsSessionKey`). Otherwise the key would open what quick unlock cannot, so the save only drops the stale item, as a rekey or encryption-settings change always does.
- Biometric unlock runs a cloud database's open sync alongside the prompt. The sync must stay free of session and list-store writes until `readDatabaseData` applies it, so a failed or abandoned prompt leaves no banner or sync issue behind.
- `cancelUnlockAttempt()` ends only a running open (refused while locked, unlocked, failed, or while Sync Now or a conflict reload replaces the tree) as a manual lock, so `finishUnlockAttempt` drops its late cloud read, KDF, biometric answer or YubiKey answer and no auto-unlock follows that cycle. A superseded attempt's cloud read reaches neither the session nor the stored reference. The iOS opening's hardware-key Cancel stays `cancelHardwareKeyRequest`, which leaves a retryable failure.
- `lastLockCause` records why an open session locked: `.manual`, `.inactivity` with the timeout then in force, `.background` (iOS backgrounding, `MacLockMonitor`) or `.system`. Callers that know the cause pass it; otherwise a request completing a deferred one keeps that request's cause (Save and Lock, Lock and Discard, an editor's resume, a failed resume authentication), else `manuallyTriggered` gives `.manual` or `.system`. Locking a session that is not open (a cancelled or failed attempt) keeps it; a successful unlock clears it.
- `MacUnlockFormModel` holds the typed password only while the form shows it: cleared before any attempt awaits (password or Touch ID) and by `windowDidShow` for any other page. It keeps a key file picked in the form across failed attempts and wipes its copy on success, Clear, a new pick and `clearSecrets()` (unlock, every lock, window close); an associated key file never replaces a pick, Clear declines it until the next lock cycle or a new association, and `reconcileKeyFileAssociation()` wipes it when the reference's association is cleared and reads a new one. An await that `clearSecrets()` or an association change overtook changes nothing. It prompts for biometrics only from `unlockWithBiometrics()` (the Touch ID button), and requests focus only after a biometric fallback, cancel or unavailable prompt. Reconnect runs one sign-in at a time, only from a failure, and returns to the form only if nothing cleared the form meanwhile. WebDAV and FTP have no hosted sign-in, so every Mac Reconnect (recovery page, status card, notice, Sync Now's failure alert) goes through `MacServerReconnect`: the connect form prefilled with the reference's server and username, accepting only its account, shown by the window's `MacServerCredentialPrompt`; the status card's also retries an unsaved change.
- `MacDatabaseOpenPage` shows the form for every `canRetryUnlock` failure (lockout included), its card offering Locate while `canRelinkDatabaseFile`, and a recovery page for the rest, with Locate only while `canRelinkDatabaseFile`, Reconnect only for `cloud.not_authenticated` and `cloud.write_scope_required`, then Try Again (`dismissOpenFailure`) and Remove from List. `MacLockedDatabaseSummary` never carries a path or server address.
- `secretAccess` ends on `lock`, every `lockRequest` (even one that unsaved work defers), backgrounding, and the start of each unlock attempt. An unlock that finishes in the background does not open it.
- `isLockPending` is true from a deferred lock request, a window-close prompt, a quit prompt that asked about the session (`holdForQuitPrompt` until `releaseQuitHold` or termination), or Retry Save and Lock's write until the lock completes or is cancelled. The Mac SSH agent offers none of that session's keys while it is set. `attachmentBytes(for:)` is the synchronous attachment read the agent uses; it moves the bytes off the main actor itself.
- While a conflict reload or Sync Now replaces the open tree, `state` is `.unlocking` but `isReplacingOpenDatabase` keeps the session open to lock triggers; they must still lock.
- A YubiKey session (`sessionUsesHardwareKey`) is read-only: a save rotates the KDF salt and would need a fresh response. Quick Launch stores the pre-key, never the response-bearing composite key.
- `DatabaseOpenFailure` diagnostics carry no file names, paths, or user data (`privacyNote`, `sanitized(_:)`). Hardware-key failures never count toward the lockout.

### Save, conflict, sync

- Stage edits through `DatabaseDraft` plus `save()`. Never mutate `rootGroup` and rebuild save state afterwards.
- `mergeAndSave()` gates its write on the conflict's `remoteSHA512` (the bytes it merged), not `openTimeSHA512`. Every failure leaves the draft and the conflict standing.
- Pending-cloud merge includes an explicit remote snapshot and all captured source ciphertexts. Only a durable output can transfer exact unchanged sources into its journal; unknown attempts and confirmed journals keep their own recovery authority. `.changeUnidentified` must never suggest Discard.
- Rekey and re-encryption refuse a dirty draft, an in-flight save, and cloud references with pending upload markers (draining them afterwards reverts the remote). The rekey stamps `lastMasterKeyChangeAt` so the drainer refuses older markers, and replaces `sessionKeyFileData` with the new key file (or none), which the next Change Master Key keeps.
- Per-reference setters (`setNickname`, the rekey's key-file association, read-only, sync policy, destination group) update only a reference still in the list; they never re-add a removed database.
- A Mac window close (`requestWindowClose`) returns `.waitForSave` while any write is in flight, locked or not; a failed rekey or re-encryption bumps `failedSettingsWriteCount`, which keeps the window open.
- `MasterKeyChangeViewModel.performConfirmedChange` runs device-owner authentication, then the rekey; the iOS view and the Mac sheet both call it after their confirmation. Only the Mac sheet reads `canSave`, which dims Save until the form requests a change; empty fields while a key file stays required count as removing the password. `EncryptionSettingsViewModel.benchmark()` derives once off the main actor on a throwaway key, runs only when asked, and waits for a cancelled derivation to finish before starting another, in any sheet (one derivation app-wide). It does not start while the database saves, and Save waits for a running one.
- `save()` no-ops behind an in-flight save. An operation holding `isSaving` (rekey, re-encryption) flushes edits that landed behind it only after confirmed completion; a committed/unknown warning retains them for an explicit operation; `importEntries` refuses to start.
- `syncCloudNow()` never discards unsaved work, never applies a response older than a save that finished mid-sync, never swaps a YubiKey session, and never pushes pending uploads.
- A completion arriving while a save conflict is on screen is held by `EntryEditCompletionGate` until `isSettled`. Reporting it races the conflict alert, which presents from the editor, and loses the dismissal.
- A successful new-entry save reports `.created` with its stable UUID; failed writes and unresolved conflicts report nothing, and Save and Lock keeps its ordinary completion without opening an entry.
- `DatabaseEditorCoordinator` guards submission and completion by lock cycle, and completion also by editor lifetime, so an old save cannot close a new editor. A completion a save conflict held is dropped when the form changed after that save, so the editor stays open and dirty with the newer input. A failed create keeps its entry UUID so a retry updates rather than duplicates.
- `AppRoutingCoordinator` applies an Open/Close destination only after the source session locks; Keep Editing or a replaced source drops it.
- Custom-icon management validates the live unlocked, writable session and refuses edits during saving or a conflict. Reads include the draft so a failed save retains visible names/deletions for retry.

### Selection, search, tags

- Recycle Bin recovery validates the live source and destination at submission. A known valid previous parent restores directly; otherwise the caller presents destination options. Restore edits use the ordinary draft/save/conflict flow and derived indexes.

- `DatabaseWorkspaceState`'s `selectedGroupID`, `selectedTag` and `selectedCollection` are mutually exclusive; only the Mac sidebar sets a collection (`MacSidebarSelection`), and creation commands then target the workspace root. Reconciliation keeps a collection and falls back to the root only when nothing is selected.
- Workspace fallbacks (default and reconciled selection, a deleted selection, New Entry and New Group with nothing chosen, the Mac Groups section) use `DatabaseViewModel.workspaceRootGroupID`. It is the visible root, except on Mac when that root is the Recycle Bin: the bin has its own sidebar row there, so the parser's wrapper stays the root. iOS keeps `visibleRootGroupID`. The wrapper (`isSyntheticRootGroup`) is never offered for Edit Group: the writer saves only its children, so its own fields would vanish on reopen.
- `workspace.entrySelection` is one session-wide set of picked entry IDs; it survives navigation, prunes entries that leave the tree or enter the recycle bin, and ends on lock, reload, or read-only transition. `moveEntries` stages one draft and refuses read-only sessions before mutation.
- While bulk selection is active, Mac single-entry edit/copy/Return and entry or group Delete commands must be unavailable. `commandEntryID`, `canEditSelectedEntry`, and `deletableSelection` share that gate.
- A permanently deleted entry's `selectedEntryID` is not cleared by `synchronizeSelections()`; the mounted detail view closes itself. Clearing it in the deleting update unmounts the detail column and wedges a pushed editor (`../Views/AGENTS.md`). A recycled entry still exists, so `deleteEntry` / `deleteGroup` clear it at once.
- `autoFillExcludedGroupIDs` resolves `<EnableSearching>` in the same inheritance order as `KPGroup.autoFillEntries`. Change both together or search and AutoFill disagree.
- Entries under an excluded group leave the search corpus but stay in the tag index and browsing lists.
- Re-including a group writes an explicit `True`, never `inherit`, or a group inside a hidden parent cannot be turned back on. An untouched `GroupEditViewModel` switch replays the stored value, because the payload is absolute.
- `effectiveTags(for:inheritedGroupTags:)` feeds both the tag index and the searchable text; `sortedGroups(_:)` orders every folder list (recycle bin pinned last). Do not add a second path for either.
- Menu commands that need workspace presentation only raise a `workspace` request counter. `canEditSelectedEntry` and `deletableSelection` decide both enablement and action so they cannot drift, and Delete stops at the request so the confirmation cannot be bypassed.

### Stale completions and forms

- Custom-field protection follows each editor row through rename and reorder. Payloads explicitly specify protection, preserving hidden credential metadata; reusing a former protected name does not protect a new row.
- `EntryEditViewModel.additionalURLs` owns writable `KP2A_URL_<n>` rows. Empty or protected fields remain custom fields; a new row takes the first unused name, and `customFieldsOutsideURLRows(of:)` keeps the detail screen from listing a URL twice.
- `EntryEditViewModel.applySetupInput` treats text with a URL scheme as a setup link (returning its parse error, form untouched) and anything else as a setup key; `setupLinkMessage(for:)` is the one wording of a link's error.
- `EntryEditViewModel` keeps imported non-Base32 TOTP bytes through unrelated edits. Explicit URI enrollment replaces those bytes even when its Base32 text matches the old field's text; later period, digit, or algorithm edits may drop the verbatim URI but must not restore the old bytes.
- `EntrySecretAction` and `AttachmentLoadCoordinator` publish only while the request and the caller's session check are current. Invalidation allows a fresh request without letting the old completion finish or clear it.
- While a Mac window's inline editor is open, `freezesWorkspace` is true (the same flag as a running save): the sidebar, entry table, search, New Entry, drops and the list-changing commands are off, and `DatabaseCommands.OpenEditor` points the entry commands at the edited entry (none for a new one). The freeze reads the editor only while it belongs to the session's current lock cycle, so a lock releases it even before the editor is closed.
- A `MacEntryDetailModel` reveal holds while the lock cycle, content revision and selected entry it was granted under stay the same, and the model is on screen. Leaving the screen mid-prompt cancels it; leaving while the entry stays selected (the inline editor) keeps the flag, leaving after a selection change, `invalidate()` and the presentation's `reset()` drop it. A saved edit changes the content revision, so it conceals. Strength is computed only from a revealed password.
- `MacQuickSearchViewModel` holds no entry data: it reads the focused database's live session on every access and re-checks the database, session, lock cycle, and content after the password prompt. Each `Result` carries its database ID; a copy needs that database to still be the focused, unlocked one, and Open in KeeForge reveals the entry only in that database's session, after the app fronted its window. Rows show the username and website host, never a code or a URL whose field reference reaches a protected value.
- `commitPendingTag()` is never called from the tag field's setter (rewriting a focused field drops keystrokes), and `normalizedTags()` includes the pending token. Both editors share these rules.
- `AppSettingsViewModel.reload()` reads persisted values without replaying effects. Mac background-delay writes persist before notifying the lock monitor; iOS has no UI or behavior for that preference. A completed Mac session lock notifies the monitor so it can invalidate the background deadline only once no session remains open.

- Pending-local merge retirement uses the receipts for the actual bytes merged. A failed retirement still applies the installed SHA/tree while keeping a recovery requirement; it never turns cleanup into proof that the target was not saved. Removal failure retains the reference and opens Database Details for source recovery.

## Tests

Unit classes in `../../KeeForgeTests/` are named `<Type>Tests`. Cover success, failure, cancellation, and stale completion there; keep UI tests for presentation, bindings, and focus. Non-obvious mappings:

- Single-session navigation and launch/enrollment integration: `AppRoutingCoordinatorTests`; enrollment expiry, destination retirement/replacement and stale deferred/sheet callbacks: `TOTPEnrollmentCoordinatorTests`; Mac launch gating, FIFO opens, duplicates and launcher/destination decisions: `MacApplicationRoutingTests`.
- Session isolation, targeted activity, stale reference callbacks, and forced removal without a mounted view: `DatabaseSessionStoreTests`. List edits and application AutoFill hook delivery: `DatabaseListViewModelTests`.
- `DatabaseViewModel` by concern: `DatabaseViewModelTests`, `DatabaseViewModelCloudSyncTests`, `AutoLockTests`, `HardwareKeyUnlockTests`, `SecretAccessGateTests`, `SortOrderTests`, `PendingUploadDrainerTests` (rekey marker cutoff), `DatabaseViewModelExpressUnlockTests` (in `ExpressUnlockTests.swift`).
- `PasswordImportViewModelTests` is in `PasswordImportTests.swift`; `CloudFileBrowserViewModelTests` covers `CloudFileBrowserSession` and `CloudFolderBrowserViewModel`.
- `DatabaseOpenFailure` has no class of its own: `DatabaseViewModelTests` and `FeedbackSubmissionServiceTests`.
- `cancelUnlockAttempt`: `DatabaseViewModelTests` (local read, biometric prompt, refused states), `DatabaseViewModelCloudSyncTests` (cloud read, biometric prefetch, Sync Now), `HardwareKeyUnlockTests` (against the iOS YubiKey Cancel). `lastLockCause`: `AutoLockTests`. `DatabaseOpeningSteps`: `DatabaseOpeningStepTests`. `canCancelUnlockAttempt` and `dismissOpenFailure`: `DatabaseViewModelTests`.
- Mac unlock: `MacUnlockFormModelTests` (fake session and panels, password lifetime, key-file association, Reconnect through the real WebDAV provider), `MacServerReconnectTests` (prefill, account check, rejected password, FTP against `FakeFTPServer`), `MacFilePanelsTests` (the `MacFilePanels` adapter through the form, its import and save panels, and a late panel result after cancellation), `MacDatabaseOpenPageTests` (every failure code's page and actions, footer, opening steps), `MacLockedDatabaseSummaryTests` (sublines and the line shared with the Databases window).
- `MacWorkspacePresentationTests` covers editor/deletion targets, existing-editor preservation, created-entry placement, the inline editor's lifecycle and freeze through every exit (cancel, save and File ▸ Save, failed save, conflict, each lock-prompt answer, ⌘W, lock, reset), enrollment into the inline editor, new-group failure/reset, per-window reset, and stale or overlapping cloud reconnects. `MacEntryEditorSessionTests` covers the editor's reveal gates, concealment on close, attachment imports across a lock, and Save, lock and window close while a sheet or popover is up.
- `DatabaseCommandsTests` covers database menu enablement (including the open-editor freeze), workspace requests, per-entry copy, any-field copy and Large Type; `EntrySecretActionTests` covers command and per-entry password authentication, stale-session rejection and `discloseEntrySecret`'s own checks. `MacEntryListModelTests` covers the entry-list snapshot, selection policy and code clock. `MacEntryDetailModelTests` covers detail fields, masking, reveal/copy/Large Type gating and every concealing trigger, history sources and formatting. `AttachmentPreviewSessionTests` covers every preview-file cleanup trigger and late loads; `PasswordGeneratorModelTests` the shared options and suggestion lifetime (the iOS sheet uses the model); `EntryVersionComparisonTests` per-field differences and concealment; `MacEntryHistorySessionTests` the History sheet's session; `EntryEditViewModelTests` `applySetupInput`.
- Editor save/reopen and failed-write retry: `KDBXCompatibilityTests`. Held completion in the real UI: `SaveConflictMergeUITests`.
