# App Support Services

This folder holds app-scoped helpers that support UI behavior and secondary product surfaces.

## Main Files

- `SettingsService.swift` decides what is local-only versus App Group-shared with the extension. It also owns `MacLockPolicy` and documents how the iOS lock-on-background default maps to the macOS screen-lock/sleep/screensaver/session-resign triggers.
- `MacLockMonitor.swift` (KeeForgeMac target only) observes the system notifications that make up the macOS auto-lock guarantee (distributed screen-lock/screensaver, workspace sleep/session-resign, the last UI-hosting window closing, app deactivation under the strict policy) and drives the existing lock/became-active paths. Notification centers are injected for unit testing (`KeeForgeTests/MacLockMonitorTests.swift`).
- `StoreKitManager.swift` supports the tip-jar/monetization flow.
- `AutoFillStatusService.swift` reports whether KeeForge is enabled as the system AutoFill provider, deep-links/one-tap-enables it via `ASSettingsHelper`, and owns the "enable AutoFill" tip dismissal flag. Main-app only; UI tests suppress the tip unless `UI_TEST_SHOW_AUTOFILL_TIP=1`. `requestEnableAutoFill` returns `true` when the system enabled the provider and `false` when the prompt closed with it still off; callers report the latter so the tap never looks like a switch that silently reset itself. The `enabledProvider` and `enableRequester` closures are the test seams for both, and `resetForTesting()` restores them.
- `MacWindowCloseGuard.swift` (KeeForgeMac target only) answers `windowShouldClose(_:)` for the close that would leave no UI-hosting window behind, so unsaved work is settled *before* the close commits — `MacLockMonitor`'s trigger fires afterwards, too late to prompt in. It lets a close with nothing unsaved through, hands an open editor its own prompt (only the editor can save the fields it holds), and presents the standard Save / Don't Save / Cancel itself for a dirty draft; the window closes once the vault locks, and Cancel keeps both window and session. It proxies each window's delegate instead of replacing it, and shares `MacLockMonitor.countRemainingHostWindows` so both halves agree on what a host window is. The prompt, the window counter, and the close itself are injected for unit testing (`KeeForgeTests/MacWindowCloseGuardTests.swift`); the vault side is the `MacWindowCloseVault` protocol that `DatabaseViewModel` conforms to.
- `ClipboardService.swift` and `HapticService.swift` wrap small device APIs used across the UI. On macOS the clipboard applies the `org.nspasteboard.ConcealedType` marker, a changeCount-guarded clear timer, and clear-on-lock; there is no Universal Clipboard exclusion on macOS (documented in Settings). Clear-on-lock has exactly one exemption, and it is iOS-only: backgrounding the app is when the user switches away to paste, so that lock keeps the copy (`preservingClipboard` in `DatabaseViewModel.lock`, issue #34). Every other lock on both platforms — inactivity timeout, explicit lock, and all the Mac `MacLockMonitor` triggers — still scrubs.
- `FeedbackSubmissionService.swift` builds and validates the in-app feedback payload (message, optional contact email, optional photo up to 5 MiB) and POSTs it as JSON to `https://feedback.keeforge.com/api/feedback` — only on explicit user submit; the send operation is an injectable closure for tests.
- `AttachmentPreviewFileStore.swift` writes short-lived *plaintext* attachment temp files for QuickLook preview/share into a dedicated `FileManager.temporaryDirectory` subdirectory with `.atomicProtected`, tracks them, and removes them on preview dismissal and database lock; `purgeOrphanedFiles()` at launch cleans leftovers from a crashed session.
- `FaviconService.swift` fetches site icons from DuckDuckGo (`https://icons.duckduckgo.com/ip3/`) for list and detail views; fetching is opt-in via `SettingsService.showWebsiteIcons` (default off). The disk cache is a plaintext per-domain fingerprint of the vault, so its location is platform-split: **iOS** uses the App Group container because the AutoFill extension reads it there; **macOS** uses the app's own sandbox container (Application Support) because its extension does not need the cache, and sharing the fingerprint would widen the App Group surface for no benefit. The mac cache-path branch must stay extension-safe (`FaviconService` is on the AutoFill allow-lists). See `../../../docs/macos-security-notes.md`. `fetchFavicon(for:cachingToDisk:)` can skip that cache, and `favicon(for:cachingToDisk:)` threads the flag through the cached-else-fetch composition: an icon being stored inside the database is already kept somewhere encrypted, so a second plaintext copy keyed by domain would widen the fingerprint above for nothing. Fetches use a dedicated **ephemeral** session with short timeouts and a fresh-session TCP retry — never `URLSession.shared`, whose persisted Alt-Svc cache makes CFNetwork hang in a QUIC handshake (no TCP fallback) on networks that drop UDP 443; see the comments on `sessionConfiguration()`.
- `FaviconIconEncoder.swift` re-encodes a downloaded favicon into the PNG bytes stored in `Meta/CustomIcons` (≤ `maximumEdge` 128 px, never upscaled, ≤ `maximumByteCount`); app target only. `downloadedIconData(for:)` is the `nonisolated async` entry point view models call and bypasses the plaintext disk cache — see the doc comments in the file for the rationale.
- `ReviewPromptService.swift` gates the App Store review prompt. iOS uses the scene-based `AppStore.requestReview(in:)`; macOS has no scene entry point, so the app injects SwiftUI's `RequestReviewAction` via `requestReviewHandler` (`SKStoreReviewController.requestReview()` is deprecated on macOS 15). `isAppStoreBuild` no-ops the prompt for a non-App-Store (Developer ID) build.
- `WhatsNewPresentationService.swift` owns the curated feature catalog and app-local set of marketing versions that have already shown What's New. Add one catalog case before each feature-bearing release, using `CHANGELOG.md`'s New Features section as source material and rewriting it as concise, user-friendly copy; platform-specific items can be filtered out of iOS or macOS.

## Change Carefully

- Even the lighter-weight helpers here can affect user-facing polish, test behavior, and extension-shared settings state.
