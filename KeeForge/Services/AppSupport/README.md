# App Support Services

This folder holds app-scoped helpers that support UI behavior and secondary product surfaces.

## Main Files

- `SettingsService.swift` decides what is local-only versus App Group-shared with the extension. It also owns `MacLockPolicy` and documents how the iOS lock-on-background default maps to the macOS screen-lock/sleep/screensaver/session-resign triggers.
- `MacLockMonitor.swift` (KeeForgeMac target only) observes the system notifications that make up the macOS auto-lock guarantee (distributed screen-lock/screensaver, workspace sleep/session-resign, app deactivation under the strict policy) and drives the existing lock/became-active paths. Notification centers are injected for unit testing (`KeeForgeTests/MacLockMonitorTests.swift`).
- `StoreKitManager.swift` and `ReviewPromptService.swift` support monetization and review prompts.
- `AutoFillStatusService.swift` reports whether KeeForge is enabled as the system AutoFill provider, deep-links/one-tap-enables it via `ASSettingsHelper`, and owns the "enable AutoFill" tip dismissal flag. Main-app only; UI tests suppress the tip unless `UI_TEST_SHOW_AUTOFILL_TIP=1`. `requestEnableAutoFill` distinguishes three outcomes that callers must keep apart: `true` (enabled), `false` (the system sheet closed with the provider still off — has to be reported, or the tap looks like a switch that reset itself), and `nil` (nothing was asked; macOS, where no extension ships yet). The `enabledProvider` and `enableRequester` closures are the test seams for both, and `resetForTesting()` restores them.
- `ClipboardService.swift` and `HapticService.swift` wrap small device APIs used across the UI. On macOS the clipboard applies the `org.nspasteboard.ConcealedType` marker, a changeCount-guarded clear timer, and clear-on-lock; there is no Universal Clipboard exclusion on macOS (documented in Settings). Clear-on-lock has exactly one exemption, and it is iOS-only: backgrounding the app is when the user switches away to paste, so that lock keeps the copy (`preservingClipboard` in `DatabaseViewModel.lock`, issue #34). Every other lock on both platforms — inactivity timeout, explicit lock, and all the Mac `MacLockMonitor` triggers — still scrubs.
- `FeedbackSubmissionService.swift` builds and validates the in-app feedback payload (message, optional contact email, optional photo up to 5 MiB) and POSTs it as JSON to `https://feedback.keeforge.com/api/feedback` — only on explicit user submit; the send operation is an injectable closure for tests.
- `AttachmentPreviewFileStore.swift` writes short-lived *plaintext* attachment temp files for QuickLook preview/share into a dedicated `FileManager.temporaryDirectory` subdirectory with `.atomicProtected`, tracks them, and removes them on preview dismissal and database lock; `purgeOrphanedFiles()` at launch cleans leftovers from a crashed session.
- `FaviconService.swift` fetches site icons from DuckDuckGo (`https://icons.duckduckgo.com/ip3/`) for list and detail views; fetching is opt-in via `SettingsService.showWebsiteIcons` (default off). The disk cache is a plaintext per-domain fingerprint of the vault, so its location is platform-split: **iOS** uses the App Group container (the AutoFill extension reads it there); **macOS** uses the app's own sandbox container (Application Support) because the group container is world-readable to the user's other processes on macOS 14. The mac cache-path branch must stay extension-safe (`FaviconService` is on the AutoFill allow-lists). See `../../../docs/macos-security-notes.md`. `fetchFavicon(for:cachingToDisk:)` can skip that cache, and `favicon(for:cachingToDisk:)` threads the flag through the cached-else-fetch composition: an icon being stored inside the database is already kept somewhere encrypted, so a second plaintext copy keyed by domain would widen the fingerprint above for nothing. Fetches use a dedicated **ephemeral** session with short timeouts and a fresh-session TCP retry — never `URLSession.shared`, whose persisted Alt-Svc cache makes CFNetwork hang in a QUIC handshake (no TCP fallback) on networks that drop UDP 443; see the comments on `sessionConfiguration()`.
- `FaviconIconEncoder.swift` re-encodes a downloaded favicon into the bytes stored in `Meta/CustomIcons`. App target only — the extension never writes icons. A favicon shown in a list is fetched and discarded, but one stored in a database is in the user's vault until they remove it, copied on every save and synced to every device, so the host does not get to decide how many bytes that costs: the image is redrawn at or below `maximumEdge` (128, never scaled *up* — a 16px favicon stays crisp for what it is) and re-encoded as PNG, with `maximumByteCount` as a fail-closed backstop for an encode that produced something unexpected. The redraw goes through a fixed 8-bit premultiplied-BGRA CoreGraphics context because favicons arrive as indexed, grayscale and 16-bit-per-channel images too, several of which are combinations CoreGraphics will not open a context for. It runs on format *or* size, not size alone: a small 16-bit-per-channel source used to skip it, carry its depth into the PNG and be refused over the byte cap, which reached the user as "no icon available" for a site that served a perfectly usable one. `downloadedIconData(for:)` is the entry point view models call — `nonisolated async`, so the cache read's disk I/O and the decode of an image whose dimensions the host chose both stay off the main actor, with only `Data` crossing back. Deliberately not `Task.detached`, which would sever the cancellation that lets closing the icon picker stop a fetch in flight.
- `ReviewPromptService.swift` gates the App Store review prompt. iOS keeps the scene-based `SKStoreReviewController` path; macOS has no scene-based entry point, so the app injects SwiftUI's `RequestReviewAction` via `requestReviewHandler` (`SKStoreReviewController.requestReview()` is deprecated on macOS 15). `isAppStoreBuild` is the hook slice 07's Developer ID build flips to no-op the prompt.
- `WhatsNewPresentationService.swift` owns the curated feature catalog and app-local set of marketing versions that have already shown What's New. Add one catalog case before each feature-bearing release, using `CHANGELOG.md`'s New Features section as source material and rewriting it as concise, user-friendly copy; platform-specific items can be filtered out of iOS or macOS.

## Change Carefully

- Even the lighter-weight helpers here can affect user-facing polish, test behavior, and extension-shared settings state.
