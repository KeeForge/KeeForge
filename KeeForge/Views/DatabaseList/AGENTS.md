# DatabaseList Views

Database picking, creation, per-database settings, master-key and encryption-settings changes, and export to Files.

## Screen Map

- On iOS/iPadOS, `DatabaseListView` owns the `EditMode` binding shared by its Edit button and list, and allows row moves only while editing. This keeps the long-press context menu from competing with the reorder gesture and leaving XCTest waiting for animations. macOS retains ordinary drag reordering without an Edit button.
- `DatabaseListView.swift` takes `isSidebarColumn` from its host — the split view's sidebar column passes `true`, the compact full-screen root leaves it `false` — and styles its list from it: `.sidebar` in a column, `.insetGrouped` full screen. It is passed in rather than read from `horizontalSizeClass`, which a sidebar column reports as compact however wide the window is. The grouped card is drawn for a plain grouped page, so over a sidebar's background it comes out *darker* than the column on iPadOS and opaque over the material on macOS. macOS also drops the view's `NavigationStack` (the split view supplies navigation there, and a stack would paint over the sidebar material).
- `DatabaseListView.swift`, `DatabaseRowView.swift`, `DatabaseDetailsView.swift`, and `CloudFileBrowserView.swift` own database picking, cloud browsing UI, rename/remove actions, read-only toggles and badges, pending-upload badges/conflict copy, "Push pending changes" actions, and settings entry points. `CloudFileBrowserView.swift` presents `WebDAVConnectView` for providers that use a manual connection form instead of hosted OAuth.
- `DatabaseDetailsView` is the one per-database settings screen behind two entry points: the list's "Database Details" context action (passes the `DatabaseListViewModel` plus an `onSelectKeyFile` closure; the list owns the key-file importer) and the unlocked database's gear button (`settings.button` in `GroupListView.swift`; passes `sessionViewModel`, which routes nickname/read-only edits through the open session and creates its own list view model with the `autoFillEnabledRefreshHandler` bridge). Its root is a hub, not a form of controls: a header (`database-details.header`) with the name and `filename · format · size`, then one `SettingsSummaryRow` per area that says what is currently set and pushes that area's page inside the sheet's `NavigationStack`. The wording comes from `DatabaseSettingsSummary.swift`, which is pure and covered by `DatabaseSettingsSummaryTests`. All state stays in `DatabaseDetailsView`; the pages are built from its section properties, so adding a setting means adding it to a page's section, never to the hub. File importers, sheets, and the export presenter hang off the `NavigationStack` rather than the hub, because the pages that raise them are pushed over it. Pages, in hub order:
  - **General** (`database-details.general.link`): Identity (`database-details.nickname-field`, `database-details.quick-launch-toggle`), Editing (`database-row.read-only-toggle`, `database-details.read-only-footer`; the toggle reads KDBX 3.1 from the session's parsed header or, from the list, from `KDBXFileSummary`), Database File (`database-details.file-format`, `database-details.file-size`, Modified), and Metadata (Added, Last Opened).
  - **AutoFill** (`database-details.autofill.link`): the per-database toggle (`database-details.autofill-toggle`, routed through `DatabaseListViewModel.setAutoFillEnabled`) and, in session context, the "Save New Entries To" row (`database-details.autofill-destination`), which opens `MoveToGroupPickerView` and stores the choice through `DatabaseViewModel.setAutoFillDestinationGroupID` — groups live in the encrypted file, so the list context cannot offer it.
  - **Master Key** (`database-details.master-key.link`): the remembered key file (`database-details.key-file-select`, Clear Key File) in both contexts, and in session context the "Change Master Key…" row (`database-details.change-master-key`, disabled while read-only), which pushes `MasterKeyChangeView`.
  - **Encryption** (`database-details.encryption.link`): the cipher, key derivation, and compression read from the file header (`database-details.encryption`, `database-details.key-derivation`, `database-details.compression`) in both contexts, and in session context the "Change Encryption Settings…" row (`database-details.change-encryption-settings`, disabled while read-only or before the file summary loads), which pushes `EncryptionSettingsView` with that summary; popping it reloads the file facts and backups, which the save changed.
  - **Cloud Sync** (`database-details.cloud-sync.link`, cloud databases only; the row's dot is green when there is no warning): provider, account, path, timestamps, status, the "Sync When Opening" toggle (`database-details.sync-on-open-toggle`), which sets `DatabaseReference.cloudSyncPolicy` in both contexts (through the session when there is one, like read-only); session context adds "Sync Now" (`database-details.sync-now`, disabled while edits are unsaved) with the last outcome underneath (`database-details.sync-outcome`), and the footer explains the policy in force.
  - **Backups & Export** (`database-details.backups.link`): Export Copy… (`database-details.export-copy`) and the backup list (`database-details.backup-row` / `database-details.backups-empty`).
  - Below the areas, session context only: "Import Passwords…" (`database-details.import-passwords`, disabled while read-only) and "App Settings" (`database-details.app-settings`).

  The hub and every page are `Form`s in a macOS sheet, so each takes `macGroupedForm()` (pages get it from the shared `page(_:content:)` builder). The Custom Name field sits in a `LabeledContent`, so it also takes `macLabelsHidden()` and `macFormFieldStyle()`.
- `DatabaseCreationView.swift` owns local and cloud database creation, including master-key input, key-file selection, destination choice, a collapsed Advanced section for cipher (AES-256/ChaCha20) and Argon2id preset selection (`database-create.cipher-picker`, `database-create.kdf-preset-picker`), and handoff to Files export or provider folder picking.
- `MasterKeyChangeView.swift` owns the Change Master Key screen, pushed from `DatabaseDetailsView`'s Master Key page — never a nested sheet — and backed by `MasterKeyChangeViewModel`. The system back button is hidden: Cancel is the single dismiss affordance, which also disables the edge-swipe pop that could abort a change mid-edit. Two `PasswordInputRow`s with the creation flow's strength warning, a key-file section (Select via its own `.fileImporter`, Clear), an error banner, and a busy overlay. Save presents a destructive confirmation dialog (extra key-file-only wording when the password fields are blank), then device-owner confirmation (`BiometricService.canAuthenticateDeviceOwner`, no-op under `-ui-testing`) before `performChange()`; an authentication failure other than a user cancel surfaces the error banner. Cancel and `onDisappear` call `cancelPendingChange()`, so dismissal mid-authentication aborts the change instead of rekeying with cleared fields. Identifiers: `master-key.new-password-field` / `master-key.new-password-visibility-button`, `master-key.confirm-password-field` / `master-key.confirm-password-visibility-button`, `master-key.keyfile.select`, `master-key.keyfile.clear`, `master-key.save`, `master-key.cancel`, `master-key.confirm-change`, `master-key.error`. Covered by `MasterKeyChangeUITests`. The `Form` takes `macGroupedForm()` and both password rows `macFormFieldStyle()`; in the default `.columns` style the key-file section fell off the bottom of the details sheet it is pushed into.
- `EncryptionSettingsView.swift` owns the Encryption Settings screen backed by `EncryptionSettingsViewModel`: cipher and key-derivation pickers with the creation choices, AES-KDF (existing databases only, with a rounds field and a footer note that it does not change the cipher), and a "(Current)" option for a setting outside them, a compression toggle, an error banner, and a busy overlay. No confirmation or device-owner prompt — the master key does not change and the save keeps a backup. While saving, the back button and interactive dismissal are disabled. Identifiers: `encryption-settings.cipher-picker`, `encryption-settings.kdf-preset-picker`, `encryption-settings.aes-kdf-rounds-field`, `encryption-settings.aes-kdf-rounds-error`, `encryption-settings.compression-toggle`, `encryption-settings.save`, `encryption-settings.error`. The `Form` takes `macGroupedForm()`.
- `PasswordImportView.swift` owns the Import Passwords screen, pushed from `DatabaseDetailsView`'s hub (`database-details.import-passwords`, session context only, disabled while read-only) and backed by `PasswordImportViewModel`. It picks a `.commaSeparatedText` file with its own `.fileImporter`, shows counts (entries, verification codes, unsupported codes kept as a protected `OTPAuth` field, rows that can't be imported), a Skip Likely Duplicates toggle, the skipped rows with their reasons, and an Import Into row that opens `MoveToGroupPickerView`. The finished state reports imported and skipped counts, says when the save is waiting on the conflict alert or failed (`password-import.save-failed`, pointing at Retry Save), and reminds the user to delete the unencrypted export file. The view discards the preview on disappear and on lock. Identifiers: `password-import.choose-file`, `password-import.import`, `password-import.done`, `password-import.import-count`, `password-import.skipped-count`, `password-import.duplicate-count`, `password-import.skip-duplicates-toggle`, `password-import.skipped-row`, `password-import.destination`, `password-import.imported-count`, `password-import.summary-skipped-count`, `password-import.error`. The `Form` takes `macGroupedForm()`.
- `KDBXExportDocument.swift` is the `FileDocument` wrapper around raw KDBX bytes for `.fileExporter`, shared by database creation and the export-copy / export-backup flows.
- `DatabaseExportPresenter.swift` owns the export-to-Files flow: `.databaseExporter(request:)` takes a `DatabaseExportRequest` (`.currentCopy` or `.backup`), loads the bytes through `DatabaseExportService`, presents `.fileExporter`, and shows a "Couldn’t Export Database" alert (`database-export.error.ok`) on failure. Entry points: the list row's "Export Copy…" context action (`database-row.export-copy-action`), the pending-upload conflict alert's Export / Discard / Cancel buttons (`pending-upload-conflict.export|discard|cancel`; Discard hands off to the row's "Discard Pending Upload?" dialog after a short delay so the alert has dismissed), and `DatabaseDetailsView`'s Backups & Export page: its Export section (`database-details.export-copy`) plus its Backups section, which lists `DatabaseExportService.backups(for:)` as `database-details.backup-row` buttons (or `database-details.backups-empty`). The details view attaches its own presenter because it is presented from two places.

Shared UI shells and the folder-wide UI rules live in `../README.md`.
