# Models Folder

This folder holds the data and logic that the rest of the app depends on. It is the most security-sensitive part of the repo.

## High-Risk Core

The canonical high-risk file list (kept in sync with `AGENTS.md`): `KDBXParser.swift`, `KDBX3Parser.swift`, `KDBXWriter.swift`, `KDBXXMLSerializer.swift`, `KDBXCrypto.swift`, `KDBXOuterCipher.swift`, `OpaqueXMLNodes.swift`, `DatabaseDraft.swift`, `EntryEdit.swift`, `Entry.swift`, `Group.swift`, `EncryptedValue.swift`, `TOTPGenerator.swift`.

- `KDBXParser.swift`, `KDBXWriter.swift`, and `KDBXCrypto.swift` implement KDBX read/write, KDF handling, XML extraction (parser side), HMAC checks, payload framing, and decompression guards. Read supports KDBX 3.1 and 4.x; write is KDBX 4 only — the writer throws `unsupportedSourceFormat` for 3.1 sources and emits only the ChaCha20 inner random stream.
- `KDBX3Parser.swift` is the legacy KDBX 3.1 read path (TLV header, AES-KDF master key derivation, stream-start-bytes authentication, hashed block stream, Salsa20/ChaCha20 inner streams), dispatched from `KDBXParser.parseWithMetaAndHeader`.
- `KDBXXMLSerializer.swift` is where all XML emission lives (invoked by `KDBXWriter`): protected-field re-encryption under the inner ChaCha20 stream, unknown-XML insertion-index replay, and re-emission of the diverted passkey private-key PEM at its original sorted custom-field position.
- `OpaqueXMLNodes.swift` holds the unknown-XML preservation type plus `KPMeta` (custom icons, recycle-bin element tracking) and `KPDeletedObject` tombstones.
- `KDBXOuterCipher.swift` centralizes outer-cipher UUID recognition, IV sizing, diagnostics, and AES-256-CBC, ChaCha20, and Twofish-256-CBC dispatch. The Twofish primitive lives in the locally vendored `Vendor/KeeForgeTwofish` package and is shared with AutoFill.
- `Entry.swift`, `Group.swift`, `EncryptedValue.swift`, and `TOTPGenerator.swift` define the in-memory representation of secrets and time-based codes. `Group.swift` also carries the tri-state `<EnableSearching>` flag (`KPInheritableBool`): `nil` means the source group had no such element and the writer must not invent one, while `.inherit` is an element that is present and explicitly defers to the parent. Making it structured shifts the opaque-XML insertion indices of the unmodelled group siblings around it, so the parser only counts it as known when its value parsed, and the writer emits it in the same position KeePass does — after `<Times>`/`<IsExpanded>`, before the children. Deliberate scope decision, not an oversight: the flag gates AutoFill only (`KPGroup.autoFillEntries`), while in-app browsing and in-app search keep using `allEntries`. KeePass reads the field as "exclude from search" generally, so KeeForge is knowingly more permissive — hiding a group from AutoFill is not the same wish as hiding it from the person who owns the database. Changing this is a product decision, not a bug fix; `DatabaseViewModel.updateSearchResults` is the single place it would change. When a user edit makes the element structured for a group that previously held an unparsable value, `DatabaseDraft` drops the preserved copy from `unknownXML` (`OpaqueXMLNodes.removeDirectChildren(named:)`) so the writer cannot emit two `<EnableSearching>` children.
- `DatabaseDraft.swift` and `EntryEdit.swift` stage in-memory entry/group creates, updates, and deletes while preserving recycle-bin behavior, protected fields, and unknown XML for later save.
- Changes here should be small, test-backed, and motivated by a real bug, format update, or security requirement.

## Other Models Here

- `DatabaseReference.swift` is the persisted identifier for a known database, including bookmarks, nicknames, quick-launch state, read-only and edit-acknowledgment flags, the per-database `autoFillEnabled` AutoFill publication gate (shipped v1.10.4), and cloud metadata.
- `CloudSyncModels.swift` describes cloud provider files and sync metadata used by the database list and sync coordinator. Optimistic concurrency uses a single opaque `rev` field; the provider-specific mapping (Dropbox rev, OneDrive cTag/eTag, WebDAV ETag → `rev`) happens in the `Services/Cloud` providers.
- `PasskeyCredential.swift` parses KeePassXC-style custom fields into passkey data used by the app and AutoFill extension, with ordered fallback to legacy Strongbox/older-KeePassXC field names (`KPEX_PASSKEY_GENERATED_USER_ID`, `KPXC_PASSKEY_USERNAME`) when the current KPEX keys are absent. The private key PEM (`KPEX_PASSKEY_PRIVATE_KEY_PEM`) is diverted out of `customFields` at parse time into the session-key-sealed `KPEntry.passkeyPrivateKey` and only decrypted just-in-time for signing; the serializer re-emits it at its original sorted custom-field position.
- `KDBXFileSummary.swift` is a credential-free summary of a KDBX file's plaintext outer header (format version, cipher, compression, KDF settings) for display in Database Details; it reuses the parser's header routines read-only and accepts a bounded file prefix.
- `Attachment.swift` defines `KPAttachment` (name + pool ref, structurally parsed from `<Entry>/<Binary>`) and `BinaryPool`, which lazily decodes `Header.innerHeaderBinaryFields` (stripping the leading protection-flag byte) on subscript access by ref. Read-only in Phase 1: the writer only ever re-emits the inner-header binary pool verbatim: no ref renumbering, no new pool entries. Dangling refs (no pool entry at that index) are tolerated and resolve to `nil` rather than failing the parse.

## Notes For Agents

- The entire folder compiles into all four app/extension targets via folder globs in `project.yml` (lines 65, 116, 163, 231), so any new file here is automatically extension- and macOS-resident. Keep it Foundation/CryptoKit-only: no UIKit/AppKit imports, no `@MainActor`.
- Secrets should stay encrypted in memory until the exact point of use.
- Keep parsing and crypto work off the main actor.
- If a format or compatibility change is unclear, check `../../docs/README.md` and the related spec before changing code.
- Twofish uses strict PKCS#7 validation. Do not add permissive padding recovery without a sanitized interoperability fixture that proves it is required.
- Relevant unit tests usually live in `../../KeeForgeTests/KDBXParserTests.swift`, `../../KeeForgeTests/KDBXWriterTests.swift`, `../../KeeForgeTests/KDBXRoundTripTests.swift`, `../../KeeForgeTests/DatabaseDraftTests.swift`, `../../KeeForgeTests/EncryptedValueTests.swift`, `../../KeeForgeTests/TOTPGeneratorTests.swift`, `../../KeeForgeTests/KeyFileProcessorTests.swift`, `../../KeeForgeTests/PasskeyTests.swift`, `../../KeeForgeTests/AttachmentTests.swift`, `../../KeeForgeTests/TwofishTests.swift`, `../../KeeForgeTests/ChaCha20Tests.swift`, and `../../KeeForgeTests/KDBXFileSummaryTests.swift`.
- `../../KeeForgeTests/KDBXCompatibilityTests.swift` and `../../KeeForgeTests/KDBXCompatibilityArtifactTests.swift` are mandatory to update for parser/writer, protected-field, or unknown-XML changes per `AGENTS.md` (the compatibility artifact gate).
