# Models Folder

This folder holds the data and logic that the rest of the app depends on. It is the most security-sensitive part of the repo.

## High-Risk Core

The canonical high-risk file list (kept in sync with `AGENTS.md`): `KDBXParser.swift`, `KDBX3Parser.swift`, `KDBXWriter.swift`, `KDBXXMLSerializer.swift`, `KDBXCrypto.swift`, `KDBXOuterCipher.swift`, `OpaqueXMLNodes.swift`, `DatabaseDraft.swift`, `EntryEdit.swift`, `Entry.swift`, `Group.swift`, `EncryptedValue.swift`, `TOTPGenerator.swift`.

- `KDBXParser.swift`, `KDBXWriter.swift`, and `KDBXCrypto.swift` implement KDBX read/write, KDF handling, XML extraction (parser side), HMAC checks, payload framing, and decompression guards. Read supports KDBX 3.1 and 4.x; write is KDBX 4 only — the writer throws `unsupportedSourceFormat` for 3.1 sources and emits only the ChaCha20 inner random stream.
- Header fields whose type IDs KeeForge does not model are preserved, not dropped: the outer header's land in `Header.unknownOuterHeaderFields` and are re-emitted after the modelled fields, and the KDBX4 inner header's (any ID other than 0x00–0x03) land in `Header.unknownInnerHeaderFields` and are re-emitted after the inner random stream ID/key and before the binary pool, byte-exact and in their original relative order. That normalizes a field the source spliced between pool entries, which is deliberate: KDBX4 defines no ordering semantics for inner-header items and KeePassXC skips IDs it does not recognize, while pool entries move as attachments change. `TestFixtures/compatibility/unknown-inner-header.kdbx` pins the behavior end to end.
- `KDBX3Parser.swift` is the legacy KDBX 3.1 read path (TLV header, AES-KDF master key derivation, stream-start-bytes authentication, hashed block stream, Salsa20/ChaCha20 inner streams), dispatched from `KDBXParser.parseWithMetaAndHeader`.
- `KDBXXMLSerializer.swift` owns all XML emission (invoked by `KDBXWriter`): protected-field re-encryption under the inner ChaCha20 stream, unknown-XML insertion-index replay, and re-emission of the diverted passkey private-key PEM at its original sorted custom-field position.
- `OpaqueXMLNodes.swift` holds the unknown-XML preservation type plus `KPMeta` (custom icons, recycle-bin element tracking) and `KPDeletedObject` tombstones.
- `KDBXOuterCipher.swift` centralizes outer-cipher UUID recognition, IV sizing, diagnostics, and AES-256-CBC, ChaCha20, and Twofish-256-CBC dispatch. The Twofish primitive lives in the locally vendored `Vendor/KeeForgeTwofish` package and is shared with AutoFill.
- `Entry.swift`, `Group.swift`, `EncryptedValue.swift`, and `TOTPGenerator.swift` define the in-memory representation of secrets and time-based codes. `Group.swift` also carries the tri-state `<EnableSearching>` flag (`KPInheritableBool`): `nil` means the source group had no such element and the writer must not invent one, while `.inherit` is an element that is present and explicitly defers to the parent. Making it structured shifts the opaque-XML insertion indices of the unmodelled group siblings around it, so the parser only counts it as known when its value parsed, and the writer emits it in the same position KeePass does — after `<Times>`/`<IsExpanded>`, before the children. Deliberate scope decision, not an oversight: the flag gates AutoFill only (`KPGroup.autoFillEntries`), while in-app browsing and in-app search keep using `allEntries`. KeePass reads the field as "exclude from search" generally, so KeeForge is knowingly more permissive — hiding a group from AutoFill is not the same wish as hiding it from the person who owns the database. Changing this is a product decision, not a bug fix; `DatabaseViewModel.updateSearchResults` is the single place it would change. When a user edit makes the element structured for a group that previously held an unparsable value, `DatabaseDraft` drops the preserved copy from `unknownXML` (`OpaqueXMLNodes.removeDirectChildren(named:)`) so the writer cannot emit two `<EnableSearching>` children. `KPGroup` additionally carries KDBX 4.1 group `<Tags>` (`tags` + `hasTagsElement`, the same three-state empty-element semantics `KPEntry` has), parsed READ-ONLY so `DatabaseViewModel` can compute effective tags (own plus every ancestor group's): KeeForge has no group-tag write surface, so the serializer only re-emits what was parsed — right after the `<EnableSearching>` block, before the child entries, the same KeePass position the parser's opaque-XML insertion indices are recorded against — and a group whose source had no element never gains one (hence no KDBX 4.0→4.1 version-bump logic exists or is allowed). The parser splits the stored text with the entry rules (`,`/`;`, trim, drop empties) and deliberately does NOT dedupe or reorder — read-time rewriting is forbidden; `TagNormalizer`'s dedupe is edit-side policy. Every `KPGroup` construction site must forward `tags`/`hasTagsElement` (`copyGroup`, `deepCopy`, `replacingChildGroup`, `applySetGroupSearchingEnabled`, `applySetGroupIcon`) or group tags silently vanish on the first unrelated edit; `KDBXCompatibilitySupport.GroupScalars` pins this.
- `DatabaseDraft.swift` and `EntryEdit.swift` stage in-memory entry/group creates, updates, and deletes while preserving recycle-bin behavior, protected fields, and unknown XML for later save. `restoreEntryVersion` makes a stored `<History>` version current again: user-visible fields come from the snapshot while `id`, `creationTime` and `unknownXML` stay with the live entry, and the replaced state is pushed onto the history unless `HistoryMaxItems`/`HistoryMaxSize` discard it — `restoreKeepsReplacedState` reports that, so the confirmation does not promise an undo it cannot deliver. History trimming decides *which* versions survive by recency, then re-emits the survivors in storage order: KDBX fixes no `<History>` order — KeePass appends oldest-first where this app prepends — so choosing by position discarded the newest versions of a KeePass-authored file, while sorting the array would rewrite that file's bytes on every save. Both caps (`HistoryMaxItems` and `HistoryMaxSize`) use the same order, and it matches `DatabaseViewModel.history(forEntryID:)`'s: undated versions last, ties by storage position. Two group edits deliberately *drop* a preserved element rather than round-tripping it, because the structured field would otherwise be written alongside a duplicate that outranks it: `setGroupSearchingEnabled` removes any preserved `<EnableSearching>`, and `setGroupIcon` removes both `customIconUUID` and any preserved `<CustomIconUUID>` (a custom icon takes precedence over `<IconID>` in KeePass, so leaving it would write the chosen standard icon but never show it).
- Changes here should be small, test-backed, and motivated by a real bug, format update, or security requirement.

## Other Models Here

- `DatabaseReference.swift` is the persisted identifier for a known database, including bookmarks, nicknames, quick-launch state, read-only and edit-acknowledgment flags, the per-database `autoFillEnabled` AutoFill publication gate (shipped v1.10.4), and cloud metadata.
- `CloudSyncModels.swift` describes cloud provider files and sync metadata used by the database list and sync coordinator. Optimistic concurrency uses a single opaque `rev` field; the provider-specific mapping (Dropbox rev, OneDrive cTag/eTag, WebDAV ETag → `rev`) happens in the `Services/Cloud` providers.
- `PasskeyCredential.swift` parses KeePassXC-style custom fields into passkey data used by the app and AutoFill extension, with ordered fallback to legacy Strongbox/older-KeePassXC field names (`KPEX_PASSKEY_GENERATED_USER_ID`, `KPXC_PASSKEY_USERNAME`) when the current KPEX keys are absent. The private key PEM (`KPEX_PASSKEY_PRIVATE_KEY_PEM`) is diverted out of `customFields` at parse time into the session-key-sealed `KPEntry.passkeyPrivateKey` and only decrypted just-in-time for signing; the serializer re-emits it at its original sorted custom-field position.
- `KDBXFileSummary.swift` is a credential-free summary of a KDBX file's plaintext outer header (format version, cipher, compression, KDF settings) for display in Database Details; it reuses the parser's header routines read-only and accepts a bounded file prefix.
- `TagNormalizer.swift` is the single implementation of the tag identity policy shared by the editor and `DatabaseViewModel`'s tag index: split free-form text on `,`, `;`, and newlines, trim, drop empties, and dedupe exact-string (so `Work` and `work` stay separate) keeping first occurrence. Normalization applies to edit-side input and derived lists only — parsed `KPEntry.tags` and `KPGroup.tags` are never rewritten on read (the parser has its own dedupe-free split for exactly that reason).
- `Attachment.swift` defines `KPAttachment` (name + pool ref, structurally parsed from `<Entry>/<Binary>`) and `BinaryPool`, which lazily decodes `Header.innerHeaderBinaryFields` (stripping the leading protection-flag byte) on subscript access by ref. Read-only in Phase 1: the writer only ever re-emits the inner-header binary pool verbatim: no ref renumbering, no new pool entries. Dangling refs (no pool entry at that index) are tolerated and resolve to `nil` rather than failing the parse.

## Notes For Agents

- The entire folder compiles into all four app/extension targets via folder globs in `project.yml`, so any new file here is automatically extension- and macOS-resident. Keep it Foundation/CryptoKit-only: no UIKit/AppKit imports, no `@MainActor`.
- Secrets should stay encrypted in memory until the exact point of use; keep parsing and crypto work off the main actor.
- If a format or compatibility change is unclear, check `../../docs/README.md` and the related spec before changing code.
- Twofish uses strict PKCS#7 validation. Do not add permissive padding recovery without a sanitized interoperability fixture that proves it is required.
- Relevant unit tests usually live in `../../KeeForgeTests/KDBXParserTests.swift`, `../../KeeForgeTests/KDBXWriterTests.swift`, `../../KeeForgeTests/KDBXRoundTripTests.swift`, `../../KeeForgeTests/DatabaseDraftTests.swift`, `../../KeeForgeTests/EncryptedValueTests.swift`, `../../KeeForgeTests/TOTPGeneratorTests.swift`, `../../KeeForgeTests/KeyFileProcessorTests.swift`, `../../KeeForgeTests/PasskeyTests.swift`, `../../KeeForgeTests/AttachmentTests.swift`, `../../KeeForgeTests/TwofishTests.swift`, `../../KeeForgeTests/ChaCha20Tests.swift`, and `../../KeeForgeTests/KDBXFileSummaryTests.swift`.
- Per `AGENTS.md`, parser/writer, protected-field, or unknown-XML changes must also update `../../KeeForgeTests/KDBXCompatibilityTests.swift` and `../../KeeForgeTests/KDBXCompatibilitySupport.swift` (the matrix tests also emit the artifacts consumed by the external `keepassxc-cli` gate).
