# Models Folder

This folder holds the data and logic that the rest of the app depends on. It is the most security-sensitive part of the repo.

## High-Risk Core

The canonical high-risk file list (kept in sync with `AGENTS.md`): `KDBXParser.swift`, `KDBX3Parser.swift`, `KDBXWriter.swift`, `KDBXXMLSerializer.swift`, `KDBXCrypto.swift`, `KDBXOuterCipher.swift`, `OpaqueXMLNodes.swift`, `DatabaseDraft.swift`, `EntryEdit.swift`, `Entry.swift`, `Group.swift`, `EncryptedValue.swift`, `TOTPGenerator.swift`.

- `KDBXParser.swift`, `KDBXWriter.swift`, and `KDBXCrypto.swift` implement KDBX read/write, KDF handling, XML extraction (parser side), HMAC checks, payload framing, and decompression guards. Read supports KDBX 3.1 and 4.x; write is KDBX 4 only — the writer throws `unsupportedSourceFormat` for 3.1 sources and emits only the ChaCha20 inner random stream. `gunzip` refuses more than `KDBXCrypto.maxDecompressedSize` (256 MiB), so the writer throws `payloadTooLarge` rather than compress a larger inner header plus XML into a file the reader could not open again; an uncompressed payload has no such limit on either side.
- Header fields whose type IDs KeeForge does not model are preserved, not dropped: the outer header's land in `Header.unknownOuterHeaderFields` and are re-emitted after the modelled fields, and the KDBX4 inner header's (any ID other than 0x00–0x03) land in `Header.unknownInnerHeaderFields` and are re-emitted after the inner random stream ID/key and before the binary pool, byte-exact and in their original relative order. That normalizes a field the source spliced between pool entries, which is deliberate: KDBX4 defines no ordering semantics for inner-header items and KeePassXC skips IDs it does not recognize, while pool entries move as attachments change. `TestFixtures/compatibility/unknown-inner-header.kdbx` pins the behavior end to end.
- `KDBX3Parser.swift` is the legacy KDBX 3.1 read path (TLV header, AES-KDF master key derivation, stream-start-bytes authentication, hashed block stream, Salsa20/ChaCha20 inner streams), dispatched from `KDBXParser.parseWithMetaAndHeader`.
- `KDBXXMLSerializer.swift` owns all XML emission (invoked by `KDBXWriter`): protected-field re-encryption under the inner ChaCha20 stream, unknown-XML insertion-index replay, and re-emission of the diverted passkey private-key PEM at its original sorted custom-field position.
- `OpaqueXMLNodes.swift` holds the unknown-XML preservation type plus `KPMeta` (custom icons, recycle-bin element tracking) and `KPDeletedObject` tombstones.
- `SecureWipe.swift` is the `memset_s` zeroing helper the parser, writer, `KDBXCrypto`, and `KeychainService` use on transient key material (`Data`, arrays, raw buffers; `wipingData(copying:)` builds a `Data` whose buffer is zeroed when its last holder — bridged `NSData` included — releases it, for the Keychain write). Pre-size multi-append key buffers with `Data(capacity:)` so a reallocation never strands the earlier bytes unwiped. The composite key itself travels as a CryptoKit `SymmetricKey` (zeroed on deallocation) from `KDBXCrypto.compositeKey` through the view models, savers, and Keychain; only buffers this code created and uniquely owns are wiped, because `Data.withUnsafeMutableBytes` on a shared buffer copies first. `Argon2.hash` calls the reference C `argon2_hash` directly (package `argon2`) so no Swift wrapper leaves unzeroed copies of the transformed key.
- `KDBXOuterCipher.swift` centralizes outer-cipher UUID recognition, IV sizing, diagnostics, and AES-256-CBC, ChaCha20, and Twofish-256-CBC dispatch. The Twofish primitive lives in the locally vendored `Vendor/KeeForgeTwofish` package and is shared with AutoFill.
- `Entry.swift`, `Group.swift`, `EncryptedValue.swift`, and `TOTPGenerator.swift` define the in-memory representation of secrets and time-based codes. `KPGroup` is a reference type; `KPGroup.deepCopy()` is the one recursive value-copy, and anything staging a modified tree copies through it first. Invariants an editor must know:
  - Element positions are load-bearing: the parser records opaque-XML insertion indices against KeePass's element order, so a structured field counts as known only when its value parsed, and the serializer must emit it at KeePass's position — `<Notes>` right after `<Name>`, `<EnableSearching>` after `<Times>`/`<IsExpanded>`, `<Tags>` right after it, all before the children; `<LocationChanged>` last of the `<Times>` children (after `<LastModificationTime>`, counted toward `timesKnownChildCount` only when parsed). The read handler's guards and the `case "Group":` arm of `recordOpaqueXML` must stay identical in their conditions or every opaque fragment after the element shifts.
  - Three-state optional elements: `<EnableSearching>` (`KPInheritableBool`; `nil` = no element, never invent one; `.inherit` = present and defers to the parent), `<Tags>` (`tags` + `hasTagsElement`) and `<Notes>` (`notes` + `hasNotesElement`) on groups — same semantics as `KPEntry`'s — and `locationChanged` on both types (`nil` = no element). A group whose source had neither element never gains one. When an edit makes `<EnableSearching>` structured for a group that held an unparsable value, `DatabaseDraft` drops the preserved copy (`OpaqueXMLNodes.removeDirectChildren(named:)`) so the writer never emits two.
  - `<EnableSearching>` gates AutoFill (`KPGroup.autoFillEntries`) and the search corpus (`DatabaseViewModel.rebuildDerivedState`, same inheritance order — change both together); browsing and the tag browser use `allEntries`.
  - Only a reparent writes `LocationChanged`: `DatabaseDraft.moveEntry`/`moveGroup` (recycling is a move; `<LastModificationTime>` stays put); new objects get `locationChanged == creationTime`; every other edit carries the value through.
  - Group tags: parser splits with the entry rules (`,`/`;`, trim, drop empties), never dedupes or reorders; `TagNormalizer`'s dedupe is edit-side (`updateGroup`'s payload). Group notes parse untrimmed. Authoring a group tag forces the header to KDBX 4.1 (`KDBXWriter.requiredMinorVersion(for:)`, `resolveHeader` writes `max(required, existing)`, never a downgrade; `<Notes>` predates 4.1 and does not count).
  - Every `KPGroup` construction site (`copyGroup`, `deepCopy`, `replacingChildGroup`, `applySetGroupSearchingEnabled`, `applySetGroupIcon`, `applyUpdateGroup`, the parser's `GroupBuilder`) must forward `tags`/`hasTagsElement`/`notes`/`hasNotesElement` or the fields vanish on the first unrelated edit; `GroupScalars` in `../../KeeForgeTests/KDBXCompatibilitySupport.swift` pins this.
- `DatabaseDraft.swift` and `EntryEdit.swift` stage in-memory entry/group creates, updates, and deletes while preserving recycle-bin behavior, protected fields, and unknown XML for later save. Invariants:
  - The serializer writes an entry's `<CustomIconUUID>` only from the preserved XML, so the display copy (`customIconUUID`) must always match those bytes. Only `setEntryIcon` and `addEntryCustomIcon` write that element: they remove any existing one and append a fresh one at the position directly after `<IconID>` — computed by `customIconUUIDInsertionIndex(for:)`, not a constant, because a parsable `<Binary>` before `<IconID>` shifts the opaque-XML positions after it. `EntryIconSelection.standard` clears both the display copy and the element; `setGroupIcon` does the same on groups (a custom icon outranks `<IconID>` in KeePass, so a leftover element would hide the chosen standard icon). `updateGroup` drops the custom icon only when `iconID` actually changed.
  - `setGroupSearchingEnabled` drops any preserved `<EnableSearching>` rather than round-tripping it, so the structured field is never written next to a duplicate that outranks it.
  - `addEntryCustomIcon` is the one edit that adds an image to `Meta/CustomIcons` (via `CustomIconXML.swift`) and points the entry at it in the same edit, updating the decoded dictionary (what the UI reads) and the preserved XML (what the writer emits) together. Identical bytes already in the database are reused (lowest UUID wins, so the edit stays a pure function of its input); the `add-entry-custom-icon` compatibility scenario pins the cycle. Like every entry edit it pushes a `<History>` version.
  - Attachments are edited through `EntryDraftPayload.attachments` on `createEntry`/`updateEntry` (`nil` keeps an updated entry's list, so callers that never show attachments cannot drop one). The draft carries the binary pool its refs point into (`binaryPoolFields`, `nil` = leave the pool to the file being replaced, which is what AutoFill and most tests do) and `write(compositeKey:header:kdfPolicy:)` puts it into the header, so every saver writes the pool the tree was edited against. A new file reuses a pool entry with identical bytes or is appended with the `0x01` flag KeePassXC writes; nothing is ever removed or renumbered, so a removed attachment's bytes stay for the history version the edit pushes, as in KeePass. A new `<Binary>` goes after the entry's existing attachments, or directly after `<Notes>` (`attachmentInsertionIndexAfterNotes`), a slot the parser reports back unchanged whatever follows it. Adding to a draft built without a pool throws `attachmentPoolUnavailable`; keeping an attachment the entry no longer has throws `attachmentNotFound`. An append that would take an index some attachment already names (a dangling ref on any entry or history version) throws `attachmentWouldClaimMissingReference` rather than silently giving that ref the new file's bytes. An append that would take the pool's inner-header bytes past `KDBXCrypto.maxDecompressedSize` throws `attachmentsTooLarge`, whatever the file's compression is, because the draft does not know the header and compression can be turned on later; the writer makes the exact check (below). The `attachments-add-remove` compatibility scenario pins the cycle against KeePassXC.
  - `restoreEntryVersion` takes user-visible fields from the snapshot, the `<Times>` expiration elements included (`EntryExpiryXML.entry(_:withExpirationOf:)`), while `id`, `creationTime`, the rest of `unknownXML`, and `customIconUUID` stay with the live entry, and pushes the replaced state onto history unless the caps discard it — `restoreKeepsReplacedState` reports whether that undo survives, so the confirmation never promises one it cannot deliver.
  - `<Times>/<ExpiryTime>` and `<Expires>` are not structured either: the parser reads them into `KPEntry.expiryTime`/`expires` for display and keeps the elements in `unknownXML`, which is all the serializer writes. `EntryDraftPayload.expiry` (`nil` = leave it alone, which is what the AutoFill URL addition sends) goes through `EntryExpiryXML` on create and update, which rewrites both elements where they stand, adds missing ones at KeePass's position (after `<LastAccessTime>`, before `<UsageCount>`/`<LocationChanged>`), collapses duplicates, and updates the display copy with them. A payload matching the entry's current expiry is a no-op, so an unchanged form never rewrites the bytes; turning expiration off writes `<Expires>False</Expires>` and keeps the stored date, as KeePass does.
  - `creatingEntries(_:inGroup:)` is the password import's bulk create: it must leave the same tree and `pendingEdits` as one `.createEntry` per draft in order, but copies the group's entry list and the edit log once, so it stays linear in the number of entries. `DatabaseDraftTests` pins the equivalence.
  - `EntryDraftPayload.protectedCustomFieldKeys` marks custom-field keys that must serialize with `Protected=True` on the create path (AutoFill passkey registration relies on it for `KPEX_PASSKEY_*`); `DatabaseDraft` intersects it with the keys that actually serialize — including the diverted passkey PEM key — before passing it as `protectedStringKeys`.
- Changes here should be small, test-backed, and motivated by a real bug, format update, or security requirement.

## Other Models Here

- `DatabaseReference.swift` is the persisted identifier for a known database, including bookmarks, nicknames, quick-launch state, the read-only flag, the per-database `autoFillEnabled` AutoFill publication gate, the `autoFillDestinationGroupID` AutoFill save group, `lastMasterKeyChangeAt`, the cloud `cloudSyncPolicy` (sync on open vs. manual), and cloud metadata.
- `PasskeyCredential.swift` parses KeePassXC-style custom fields into passkey data used by the app and AutoFill extension, with ordered fallback to legacy Strongbox/older-KeePassXC field names (`KPEX_PASSKEY_GENERATED_USER_ID`, `KPXC_PASSKEY_USERNAME`) when the current KPEX keys are absent. The private key PEM (`KPEX_PASSKEY_PRIVATE_KEY_PEM`) is diverted out of `customFields` at parse time into the session-key-sealed `KPEntry.passkeyPrivateKey` and only decrypted just-in-time for signing; the serializer re-emits it at its original sorted custom-field position.
- `HardwareKey.swift` holds a database's YubiKey setting (`HardwareKeyConfiguration`: NFC, slot 1 or 2), the typed `HardwareKeyError`, and `ChallengeResponseKey`, the KeePassXC-compatible derivation: the challenge is the KDBX 4 KDF salt (Argon2 salt or AES-KDF seed) PKCS#7-padded to 64 bytes, and the composite key becomes `SHA256(preKey || SHA256(response))`, where `KDBXCrypto.preKey` is the concatenation `compositeKey` hashes. KDBX 3.1 files are refused as `unsupportedDatabase`: KeePassXC folds the response in after the KDF there. A KDBX 4 file carrying the legacy AES-KDF UUID is accepted, because that is how KeePassXC writes its KDBX 4 AES-KDF. The parser is untouched; a hardware-key unlock only changes the composite key handed to it. The removed transport value from the 1.17 beta decodes as NFC to preserve the existing database list; it is never offered or encoded. `../../TestFixtures/challenge-response.kdbx` (Argon2d) and `challenge-response-aeskdf.kdbx` pin the derivation against pykeepass-authored files.
- `KDBXFileSummary.swift` is a credential-free summary of a KDBX file's plaintext outer header (format version, cipher, compression, KDF settings) for display in Database Details; it reuses the parser's header routines read-only and accepts a bounded file prefix.
- `KDFExecutionPolicy.swift` is the resource budget for running an attacker-controlled Argon2 configuration (peak memory, memory × iterations total work, parallelism). Every parse/write entry point takes an explicit `kdfPolicy` — `.mainApp` in the app targets, `.autoFillExtension` in the AutoFill coordinators. The two policies differ only in peak memory (the extension's ceiling backstops `AutoFillMemoryLimit`'s runtime check and covers macOS); work and parallelism bounds are deliberately identical so the static policy never refuses a vault in one context that the other opens. Format validity (RFC 9106 minimums, Argon2 version byte) is checked separately and throws `kdfParameterOutOfRange`; a config over budget throws the localized `kdfResourceLimitExceeded` instead. Never clamp — run the exact stored values or reject.
- `OTPAuthURI.swift` parses an `otpauth://totp/...` enrollment URI into typed fields (canonical unpadded Base32 secret, issuer/account from the `issuer` param or label, period/digits/algorithm with RFC 6238 defaults) while keeping the trimmed input verbatim in `rawURI` for KeePassXC-compatible protected `otp`-field storage. Rejections are typed (`OTPAuthURIError`): non-otpauth schemes, non-TOTP types (HOTP, Steam's `encoder=steam`), missing/undecodable secrets, and out-of-range parameters. Duplicate query names resolve first-wins, matching the parser's otpauth handling.
- `TagNormalizer.swift` is the single implementation of the tag identity policy shared by the editor and `DatabaseViewModel`'s tag index: split free-form text on `,`, `;`, and newlines, trim, drop empties, and dedupe exact-string (so `Work` and `work` stay separate) keeping first occurrence. Normalization applies to edit-side input and derived lists only — parsed `KPEntry.tags` and `KPGroup.tags` are never rewritten on read (the parser has its own dedupe-free split for exactly that reason).
- `KDBXMerger.swift` reconciles two parses of the same database record by record, in the style of KeePass 2.x Synchronize / KeePassXC merge: UUID matching across the whole tree, newest-`LastModificationTime`-wins at entry granularity with the loser pushed into history, history union re-trimmed by the database's own limits, `LocationChanged`-driven moves (recycling is a move), tombstone union with timestamp-gated deletion and edit-after-delete resurrection, and a best-effort custom-icon splice. Both sides must be parsed with the same session key: protected values then graft across without a decrypt/reseal cycle, and content equality compares plaintext, because `EncryptedValue` re-seals with a fresh nonce and equal secrets never have equal ciphertext. It returns a tree and meta that alias neither input (`KPGroup` is a reference type, so remote subtrees are grafted through `deepCopy()`) plus a summary of what changed, or declines with a typed blocker — today only a diverged inner-header binary pool that something actually references, since the merged tree is written with the local side's pool and refs are never renumbered. A local pool that only extends the remote's (files an unsaved edit appended) is not divergence, unless a remote ref, history included, points into the extension and would be handed a local file it never held. Merging the same remote twice must be a no-op, which is why the summary counters are deltas against the local side and why a losing version is only pushed when an equal snapshot is not already stored.
- `EntryHistoryTrimmer.swift` is the `HistoryMaxItems`/`HistoryMaxSize` policy, shared by `DatabaseDraft` (which applies it whenever an edit pushes a version) and `KDBXMerger` (which re-applies it to a merged history union). Two copies would be free to disagree about which versions a merge is allowed to keep. It chooses survivors by recency (undated versions last, ties by storage position — the same order as `DatabaseViewModel.history(forEntryID:)`) but re-emits them in storage order: KDBX fixes no `<History>` order and KeePass appends oldest-first where this app prepends, so choosing by position would discard a KeePass-authored file's newest versions and sorting the array would rewrite its bytes on every save.
- `CustomIconXML.swift` adds an image to `Meta/CustomIcons` without rewriting the icons already there. That element is preserved as one opaque fragment and replayed verbatim, which is why a foreign database's icons survive a save untouched; rebuilding it from `KPMeta.customIcons` would normalize `<Icon>` child order, KDBX 4.1's optional `<Name>`/`<LastModificationTime>`, and each writer's own base64 wrapping — none of which this app models. So the new icon is spliced in before the closing tag instead, and only the appended element is ours. Base64 cannot contain `<` or `>`, which is what makes searching the fragment's own text for its closing tag unambiguous. The written `<Icon>` deliberately carries only `<UUID>` and `<Data>`: `<Name>` and `<LastModificationTime>` are 4.1 additions that would oblige `KDBXWriter.requiredMinorVersion(for:)` to raise the file's minor version, turning an icon download into a format upgrade the user never asked for. The parser renders every preserved fragment through a start/end tag pair, so a captured `<CustomIcons>` always closes explicitly even when the source file wrote `<CustomIcons/>` — that is the one shape the splice handles. Anything else returns `nil` and the edit fails: a fragment this cannot splice is one it does not understand, and rebuilding the element from `KPMeta.customIcons` would drop every icon whose bytes this app does not model, which is the silent data loss the type exists to prevent.
- `FieldReferenceResolver.swift` resolves KeePass field references (`{REF:<Wanted>@<SearchIn>:<Text>}`) against a snapshot of the tree: T/U/P/A/N/I wanted codes, T/U/P/A/N/I/O search codes, `@I` by 32-hex UUID, otherwise case-insensitive substring with the first hit in tree order, recursion capped at `maxDepth` so cycles terminate, and anything unresolvable left literal (KeePass behavior). Wanted/SearchIn `P` needs the session key. Read side only — display, copy, AutoFill fill (`DatabaseViewModel.resolvingFieldReferences`, `CredentialProviderCoordinator.completeRequest`); the editor, drafts, savers, and export never see resolved values, or a save would overwrite the reference with its target.
- `EntryExpiryXML.swift` splices an entry's expiration into its preserved `<Times>` XML (see the `DatabaseDraft` invariants above for why it is a splice); `KDBXDateEncoding.swift` is the KDBX 4 timestamp encoder (little-endian Int64 seconds since 0001-01-01 UTC, base64) the serializer and that splice share, plus `kdbxStoredDate`, the whole-second value a written date reads back as.
- `KDBXUUIDEncoding.swift` is the one place a UUID becomes the base64 of its 16 raw bytes, which is how KDBX stores every UUID. It also holds the 32-hex `kdbxHexString` / `init(kdbxHexString:)` pair that field references name entries by. Single-sourced on purpose: `KDBXXMLSerializer` writes structured elements from it and `DatabaseDraft` builds the preserved `<CustomIconUUID>` fragment from it, and two encoders would be free to drift on a detail the format does not forgive.
- `CSVReader.swift` is an RFC 4180 reader over Unicode scalars (Swift folds `"\r\n"` into one `Character`, which would hide a record break). Quoted fields keep commas, doubled quotes, and line breaks; blank lines are not records; a leading BOM is dropped. A stray quote marks the record `isMalformed` instead of guessing its boundaries, and an unterminated quote rejects the whole file, since every later row would be read as part of it.
- `PasswordImport.swift` turns a password export into `EntryDraftPayload`s before anything touches the database. `ApplePasswordsCSVImporter` accepts only the Passwords app's columns (`Title,URL,Username,Password,Notes,OTPAuth`, matched by name and case-insensitively; `Notes`/`OTPAuth` optional for older Safari exports) and rejects any other column, so an arbitrary CSV is never treated as compatible and no column is dropped unseen. Values are kept verbatim. A TOTP `OTPAuth` link becomes a `TOTPConfiguration` with the link stored verbatim, the same shape as the editor's enrollment; any other link is kept in the protected `OTPAuth` custom field. Rows are numbered by record with the header as row 1, and each skipped row carries a reason. `likelyDuplicateRows(existing:)` matches on website (trimmed; scheme and host case-insensitive, user info, path, query, and fragment as written) plus user name, falling back to title when there is no website, against the database and earlier rows of the file. The preview holds plaintext passwords, so callers keep it only while the import screen is open. Files over `maximumFileSize` are refused before they are read.
- `Attachment.swift` defines `KPAttachment` (name + pool ref, structurally parsed from `<Entry>/<Binary>`) and `BinaryPool`, which lazily decodes `Header.innerHeaderBinaryFields` (stripping the leading protection-flag byte) on subscript access by ref. The writer emits whichever pool it is handed; refs are never renumbered and pool entries are never removed or reordered. Dangling refs (no pool entry at that index) are tolerated and resolve to `nil` rather than failing the parse.

## Notes For Agents

- Every file here is extension- and macOS-resident. Keep it Foundation/CryptoKit-only: no UIKit/AppKit imports, no `@MainActor`.
- Secrets should stay encrypted in memory until the exact point of use; keep parsing and crypto work off the main actor.
- If a format or compatibility change is unclear, check `../../docs/README.md` and the related spec before changing code.
- Twofish uses strict PKCS#7 validation. Do not add permissive padding recovery without a sanitized interoperability fixture that proves it is required.
- Relevant unit tests usually live in `../../KeeForgeTests/KDBXParserTests.swift`, `../../KeeForgeTests/KDBXWriterTests.swift`, `../../KeeForgeTests/KDBXRoundTripTests.swift`, `../../KeeForgeTests/DatabaseDraftTests.swift`, `../../KeeForgeTests/KDBXMergerTests.swift`, `../../KeeForgeTests/EncryptedValueTests.swift`, `../../KeeForgeTests/TOTPGeneratorTests.swift`, `../../KeeForgeTests/FieldReferenceResolverTests.swift`, `../../KeeForgeTests/KeyFileProcessorTests.swift`, `../../KeeForgeTests/PasskeyTests.swift`, `../../KeeForgeTests/AttachmentTests.swift`, `../../KeeForgeTests/TwofishTests.swift`, `../../KeeForgeTests/ChaCha20Tests.swift`, and `../../KeeForgeTests/KDBXFileSummaryTests.swift`.
- Per `AGENTS.md`, parser/writer, protected-field, or unknown-XML changes must also update `../../KeeForgeTests/KDBXCompatibilityTests.swift` and `../../KeeForgeTests/KDBXCompatibilitySupport.swift` (the matrix tests also emit the artifacts consumed by the external `keepassxc-cli` gate).
