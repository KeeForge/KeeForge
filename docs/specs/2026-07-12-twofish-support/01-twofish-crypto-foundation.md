# Slice 01: Twofish Crypto Foundation

> Parent: [`epic.md`](./epic.md) · Depends on: —

## Goal

Add a self-contained, testable Twofish primitive and strict Twofish-256-CBC/PKCS#7 implementation without changing which KDBX files KeeForge accepts yet.

## Scope

**In:**

- Add local Swift package `Vendor/KeeForgeTwofish`.
- Vendor pristine `twofish.c` and `twofish.h` from the Niels Ferguson v0.3 distribution, retaining the complete copyright, license, disclaimer, and version history.
- Add a small KeeForge-owned C shim only where needed for initialization and optimizer-resistant cleanup; do not edit the upstream files.
- Add a Swift wrapper for checked single-block operations and KDBX's Twofish-256-CBC mode with strict PKCS#7.
- Link the package to the main app, AutoFill extension, and unit-test target.

**Out:**

- Recognizing the KDBX Twofish UUID.
- Parser, writer, diagnostics, fixture, save-path, or UI changes.
- A streaming API or cipher-selection abstraction.

## Implementation requirements

### Source and package boundary

- Pin provenance in the package README or source comment to the [official Twofish download page](https://www.schneier.com/academic/twofish/download/) and Ferguson version 0.3. Record a SHA-256 for each pristine upstream file so future updates are reviewable.
- The package has no network dependency and no product beyond the single `KeeForgeTwofish` library.
- Compile the C source once for every consumer through Swift Package Manager. Do not duplicate C files into app targets.
- Keep the wrapper Foundation-only plus the C module; it must remain valid in an app extension.

### Primitive contract

- Expose block encryption/decryption for 16-, 24-, and 32-byte keys so all official KAT sizes can be tested.
- Require exactly one 16-byte input block and return exactly one 16-byte output block.
- Reject every unsupported key or block length with a typed error; never truncate, pad, or return the input unchanged.
- Run `Twofish_initialise` through one Swift lazy/static once token. Concurrent callers must never race initialization or rerun self-tests.
- Allocate a fresh expanded key schedule per operation. Clear it and temporary mutable C/Swift buffers in `defer`/cleanup paths for success and failure. Use a cleanup routine that the optimizer cannot remove; do not claim the caller's immutable `Data` storage has been erased.

### CBC and padding contract

- KDBX CBC accepts only a 32-byte key and 16-byte IV.
- Encryption always appends PKCS#7 padding. Empty plaintext produces one full `0x10` block; block-aligned plaintext receives an additional full padding block.
- Decryption rejects empty ciphertext and ciphertext whose length is not a multiple of 16.
- Padding length must be 1...16 and every byte in the final padding span must match. Validate the full span before returning one generic decryption error; do not expose which padding byte failed.
- CBC state, key schedule, and temporary plaintext/ciphertext blocks are operation-local. The API must be safe for simultaneous calls from unrelated tasks.
- Do not log keys, IVs, plaintext, ciphertext, expanded schedules, or padding bytes. The package itself should not use `print`, `NSLog`, or `os_log`.

## Testing

### Unit: `TwofishTests.swift`

- Official block known-answer tests for 128-, 192-, and 256-bit keys assert exact ciphertext and reverse decryption, using vectors published with Twofish/Ferguson rather than values generated by the implementation under test.
- An independent 256-bit CBC vector uses key bytes `00...1F`, descending IV bytes `0F...00`, and plaintext bytes `00...2F`; assert exact PKCS#7 ciphertext and reverse decryption. Generate the fixed expected ciphertext once with Botan 3.x, then embed it with the Botan version/command in the test comment rather than calculating it at test runtime.
- PKCS#7 round trips cover plaintext lengths 0, 1, 15, 16, 17, and a multi-block length; explicitly assert the extra full padding block for length 16.
- Validation rejects 31- and 33-byte KDBX keys, 15- and 17-byte IVs, empty ciphertext, and non-block-aligned ciphertext.
- Invalid padding covers zero, greater than 16, a mismatched last byte, a mismatch earlier in the claimed padding span, and malformed full-block padding. Every case produces the same public decryption error.
- One hundred concurrent encrypt/decrypt operations with distinct inputs produce deterministic results and no crash/data race. Add a test-only initialization counter or injectable hook that proves the upstream initializer ran once without exposing such state in release builds.
- Capture test-process logging around success and failure cases and assert none of the unique key/plaintext/ciphertext sentinel strings appear.

Run:

```bash
xcodegen generate
xcodebuild test -project KeeForge.xcodeproj -scheme KeeForge \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' \
  -only-testing:KeeForgeTests/TwofishTests -quiet
```
