# Browser extension

Owns the Manifest V3 extension, browser-side protocol/crypto/storage, native port lifecycle, development mock, packaging and Node tests. Owns popup, pairing and inline-menu UI, browser locales, and isolated-world field discovery/injection.

- Plain JavaScript and WebCrypto only; no packages, bundler or remote code. Content scripts are classic, self-contained scripts; extension pages/background use ES modules.
- Permissions are nativeMessaging, activeTab, scripting, storage, plus HTTPS and loopback HTTP host access. Persistent isolated content scripts run in matching frames. Only the inline page and its transitive packaged assets are web accessible, using dynamic URLs on Chrome. Popup and pairing pages must remain absent from that list.
- Content discovery must not send any background/native request before a trusted field-button click. Icons must not reflect database state, matches or counts. Never alter field attributes, styles, padding or wrappers. Keep the UI host zero-sized (children fixed-positioned): a viewport-sized overlay occludes child frames' menus for visibility tracking. Cap discovery and buttons; traverse only open shadow roots; update geometry on events, not a perpetual animation-frame loop. An orphaned copy (extension updated or removed) removes its UI. Keep the key SVG in one constant.
- Credential lists render only in extension contexts: popup or cross-origin inline iframe inside one closed shadow root. Never send metadata, counts or credentials to page scripts or the content-script UI; iframe messages contain only bounded height or close. Validate their source window and extension origin.
- An inline session belongs to one browser-supplied tab/frame/document/origin and an unpredictable token. A new session replaces the previous session for that tab. Authenticate every menu API call by extension id, exact inline-page URL, same tab and current token. The document pin remains independent of the menu token. Close revokes the session; no automatic credential retries.
- Inline actions require trusted events, a visible document, 300 ms since opening and since the rows last changed, and the menu continuously fully visible (one-pixel tolerance for sub-pixel clipping) for 300 ms. When visibility-v2 exists, require its isVisible result with trackVisibility/delay 100; Firefox's fallback cannot detect occlusion/transparency. Top-level inline pages must be inert. These mitigate clickjacking; the embedding site still controls its surroundings.
- Origins come only from browser sender data and independent tab/frame inspection. Refuse opaque origins and insecure non-loopback HTTP. Missing sender.origin on Firefox is checked against sender.url and the independently inspected document origin.
- Fill only the chosen frame after an in-frame origin re-check. Require a current popup selection or inline session. Every selection creates an unpredictable per-document isolated-world pin; verify it at selection, matching, after credential release and inside filling, in addition to documentId where available. Older Firefox uses one frame id plus the same token/origin checks. Never submit a form.
- Inline filling retains the original field reference across iframe focus, and refuses a removed field or changed field kind. Login fields request username/password; code fields filter to hasTotp and request only the code. Secondary code actions remain code-only.
- A code-only fill rejects a reply with username/password; a login fill rejects a code. Passwords go only into password inputs. Recheck every input's allowed type, visibility, connection and owner document before its native setter; failure stops further writes and reports not filled.
- Probe, fill and icon discovery share one self-contained function body. Read ancestor DOM members through the element prototypes: a form's named controls (e.g. `<input name="hidden">`) shadow its own properties. The classic script contains a checked copy: run `node tools/sync-content.mjs` after changing fillDocument. The build and Node tests reject drift. Preserve conservative clipping/masking, inert/closed-details and ancestor visibility checks, overflow/viewport intersection and open-shadow focus handling.
- Popup reopening retries connection failures; pairing polling preserves terminal outcomes. A missing popup pin reruns selection before presenting rows and never retries a credential action automatically. Inline state polling runs once a second only while visible, and on focus; do not recreate identical rows or disrupt keyboard focus on every reply id.
- Never retain credentials after injection, cache matches across menu/popup openings, or log site/vault/secret data. Keep the client private key non-extractable in IndexedDB; close/discard session state on protocol errors. Serialize inbound/outbound crypto independently.
- Change docs/browser-bridge-protocol.md whenever the wire contract changes. Inline menus do not change it.

- `theme.css` owns shared light/dark tokens and row, section, button and status primitives; popup and pairing styles own only their layout. Render untrusted entry metadata through textContent and preserve native button keyboard behavior. Monochrome glyphs use CSS masks so light/dark color is inherited.
- Toolbar PNGs derive from `images/icon.svg` and `images/icon-16.svg` through `tools/render-icons.mjs`; re-render and commit them with any artwork change. `tools/screenshot-ui.mjs` checks the shipped page renderers using stubbed runtime replies in a temporary headless Chrome profile; screenshots require visual review and do not establish native-host or Touch ID integration.

Run `cd BrowserExtension && env -u NODE_USE_SYSTEM_CA node --test`; zero skips, no dependencies or Xcode. `tools/build.sh` produces deterministic Chrome/Firefox archives and unpacked copies under ignored `build/`; Firefox removes Chrome-only world/use_dynamic_url keys and uses its default isolated world.

Tests cover protocol/connection/native framing, Swift vectors, popup/frame selection and lost-pin recovery, fake-DOM native filling and visibility, shared-function equality, no discovery traffic, inline sender authentication/session replacement/revocation, login/code-only behavior, post-authentication navigation and close-on-fill, visibility-v2/fallback event gating and sub-pixel tolerance, form named-control shadowing, zero-sized host and orphan teardown, browser labels and locale completeness. `tools/browser-check.mjs` exercises production fill/probe in real Chrome; `tools/inline-browser-check.mjs` loads the shipped manifest through the debugging pipe with a disposable `mock-host.mjs --control` host and loopback HTTP/HTTPS pages, and must pass after inline, content-script, manifest or CSP changes. Chrome's extension-page stylesheet sets `body` to 75%; inline.css resets it. See README.md for browser-validation gaps.
