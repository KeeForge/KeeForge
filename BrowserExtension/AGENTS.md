# Browser extension

Owns the Manifest V3 extension, browser-side protocol/crypto/storage, native port lifecycle, development mock, packaging and Node tests. Owns popup, pairing and inline-menu UI, browser locales, and isolated-world field discovery/injection.

- Plain JavaScript and WebCrypto only; no packages, bundler or remote code. Content scripts are classic, self-contained scripts; extension pages/background use ES modules.
- Permissions are nativeMessaging, activeTab, scripting, storage, plus HTTPS and loopback HTTP host access. Persistent isolated content scripts run in matching frames from document_start, so their capture listeners precede any page listener; the UI waits for the DOM and for the first input, in the document or in an open shadow root (observed once found, at most 100). Only inline.html is web accessible (its own subresources load without listing in Chrome and Firefox), using dynamic URLs on Chrome. Popup and pairing pages must remain absent from that list.
- Content discovery must not send any background/native request before a trusted field-button click. Icons must not reflect database state, matches or counts. Never alter field attributes, styles, padding or wrappers (the host may be appended inside a top-layer element). Keep the UI host zero-sized (children fixed-positioned): a viewport-sized overlay occludes child frames' menus for visibility tracking. The host lives in the fields' top-layer element (modal dialog, fullscreen element, open popover) when there is one, because a modal dialog makes everything outside it inert. Buttons use our own colours, never the field's. Cap the inputs examined (not elements visited) and the buttons; traverse only open shadow roots; no host, observer or timer on a document without inputs; update geometry on events, never a perpetual animation-frame loop or poll except while a menu is open. Sandboxed (opaque-origin) frames and frames too small for the menu get no buttons. An orphaned copy (extension updated or removed) removes its UI. The key glyph is images/key.svg; content.js holds a test-checked copy of its path because a page-visible extension image URL would expose the extension.
- Credential lists render only in extension contexts: popup or cross-origin inline iframe inside one closed shadow root. Never send metadata, counts or credentials to page scripts or the content-script UI. The menu frame never posts to the page: its size is fixed (independent of rows and state) and closing goes through the background to the recorded frame. Popup and inline rows share `src/rows.js` and theme.css.
- An inline session belongs to one browser-supplied tab/frame/document/origin and an unpredictable token. A new session replaces the previous session for that tab. Authenticate every menu API call by extension id, exact inline-page URL, same tab and current token. The first inline document to call owns the session; a call from another document closes it. The document pin remains independent of the menu token; popup selection closes the tab's menu before replacing the pin. Close revokes the session; no automatic credential retries.
- Inline actions require trusted events, a visible document, 300 ms since opening and since the rows last changed, and the menu continuously fully visible (one-pixel tolerance for sub-pixel clipping) for 300 ms. When visibility-v2 exists, require its isVisible result with trackVisibility/delay 100; without it (Firefox) a fill needs a second click on a confirm button at a random offset. The content script closes the menu when its field or frame moves by more than a pixel, the viewport or URL changes, its host is restyled, or the frame loads a second document. Top-level inline pages must be inert. These mitigate clickjacking; the embedding site still controls its surroundings.
- Origins come only from browser sender data and independent tab/frame inspection. Refuse opaque origins and insecure non-loopback HTTP. Missing sender.origin on Firefox is checked against sender.url and the independently inspected document origin.
- The popup chooses the focused frame, else the frame last clicked or typed in (trusted events only; never script focus) while a field is still its active element, else the top frame. Fill only the chosen frame after an in-frame origin re-check. Require a current popup selection or inline session. Every selection creates an unpredictable per-document isolated-world pin; verify it at selection, matching, after credential release and inside filling, in addition to documentId where available. Older Firefox uses one frame id plus the same token/origin checks. Never submit a form.
- Inline filling retains the original field reference across iframe focus, and refuses a removed field or changed field kind. Login fields request username/password; code fields filter to hasTotp and request only the code; a user-name step (no password in its form) injects only the user name. Secondary code actions remain code-only. Readonly-until-focus passwords are decorated and focused before writing.
- A code-only fill rejects a reply with username/password; a login fill rejects a code. Passwords go only into password inputs. Recheck every input's allowed type, visibility, connection and owner document before its native setter; failure stops further writes and reports not filled.
- Probe, fill and icon discovery share one self-contained function body. Read ancestor DOM members through the element prototypes: a form's named controls (e.g. `<input name="hidden">`) shadow its own properties. The classic script contains a checked copy: run `node tools/sync-content.mjs` after changing fillDocument. The build and Node tests reject drift. Preserve conservative clipping/masking, inert/closed-details and ancestor visibility checks, overflow/viewport intersection and open-shadow focus handling.
- Popup reopening retries connection failures; pairing polling preserves terminal outcomes. A missing popup pin reruns selection before presenting rows and never retries a credential action automatically. Inline state polling runs once a second only while visible, and on focus; do not recreate identical rows or disrupt keyboard focus on every reply id.
- Never retain credentials after injection, cache matches across menu/popup openings, or log site/vault/secret data. Keep the client private key non-extractable in IndexedDB; close/discard session state on protocol errors. Serialize inbound/outbound crypto independently.
- Change docs/browser-bridge-protocol.md whenever the wire contract changes, in the same commit. Inline menus do not change it. The doc separates the shared contract (sections 1–8) from per-platform transport sections (section 9 is macOS); the extension depends only on the shared contract, so keep platform assumptions out of its code and copy.

- `theme.css` owns shared light/dark tokens and row, section, button and status primitives; popup and pairing styles own only their layout. Render untrusted entry metadata through textContent and preserve native button keyboard behavior. Monochrome glyphs use CSS masks so light/dark color is inherited.
- Toolbar PNGs derive from `images/icon.svg` and `images/icon-16.svg` through `tools/render-icons.mjs`; re-render and commit them with any artwork change. `tools/screenshot-ui.mjs` checks the shipped page renderers using stubbed runtime replies in a temporary headless Chrome profile; screenshots require visual review and do not establish native-host or device-owner prompt integration.

Run `tools/ci.sh` before handing off extension work: it is the `browser-extension` CI job (Node tests with zero skips, content sync, two identical builds, `check-build.mjs`, `render-icons.mjs --check`, then the Chrome and Firefox checks against `build/chrome` and `build/firefox`). The Node tests alone are `cd BrowserExtension && env -u NODE_USE_SYSTEM_CA node --test`; no dependencies or Xcode. Real-browser tools take browsers from `CHROME`/`FIREFOX` and the extension from `EXTENSION_DIR`; keep them free of macOS-only paths. `tools/build.sh` produces deterministic Chrome/Firefox archives and unpacked copies under ignored `build/`; Firefox removes Chrome-only world/use_dynamic_url keys and uses its default isolated world. `test/origin-fixtures.test.js` runs the app's origin cases (`../TestFixtures/browser-bridge/origins.json`) against `protocol.js`, listing each case where the extension's canonical-form check deliberately differs; the fixtures are never packaged, and a change in origin handling on either side updates the fixtures or that list in the same commit.

Tests cover protocol/connection/native framing, no page messaging, close on movement/restyle/second load, the Firefox two-step confirm, first-step and readonly fields, the input cap, document_start listeners, exact manifest permissions, hosts, content script, web-accessible list, CSP, versions and ids, every referenced file, the single key glyph, Swift vectors, popup/frame selection and lost-pin recovery, fake-DOM native filling and visibility, shared-function equality, no discovery traffic, inline sender authentication/session replacement/revocation, login/code-only behavior, post-authentication navigation and close-on-fill, visibility-v2/fallback event gating and sub-pixel tolerance, form named-control shadowing, zero-sized host and orphan teardown, browser labels and locale completeness, the inline menu's Unlock on a `locked` reply, the end-to-end driver's browser search and `browser-missing` failure, and source rules (no packages, logging, HTML injection, icon changes or page messaging). `tools/browser-check.mjs` exercises production fill/probe in real Chrome; `tools/inline-browser-check.mjs` loads the shipped manifest through the debugging pipe with a disposable `mock-host.mjs --control` host (whose `locked` scenario answers `matches` with `locked` errors as the app does) and loopback HTTP/HTTPS pages, and must pass after inline, content-script, manifest or CSP changes; it also measures the real toolbar popup (opened by `chrome.action.openPopup()`) at 340 px in each mock state, and asserts no overflow, clipping or sub-4.5:1 text on each menu state. Its click retries are budgeted (two per run), so they cannot hide a refused settled click. `screenshot-ui.mjs` applies the same `layout-probe.mjs` assertions to every popup and pairing capture in all locales; layout and contrast are asserted, not pixel-diffed. `check-build.mjs` checks the archives: shipped files only, no development key, the `MARKETING_VERSION` stamp and every referenced file. `tools/e2e-browser.mjs` drives the same real Chrome against the signed app's embedded host for `KeeForgeMacUITests/MacBrowserExtensionUITests`; it writes the native-host manifest only into its temporary profile, and never returns a password, only its length and SHA-256. Keep its command list in README.md and its helpers, and the one browser discovery every tool uses, in `tools/chrome-cdp.mjs`. `tools/firefox-check.mjs` installs build/firefox over WebDriver BiDi and checks buttons, embedding and that the page learns neither messages nor the UUID. Chrome's extension-page stylesheet sets `body` to 75%; inline.css resets it. See README.md for browser-validation gaps.
