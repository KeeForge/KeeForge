# KeeForgeMacUITests

**Scope:** XCUITest smoke suite for the native macOS app (scheme `KeeForgeMac`). It is a thin layer by design; see "macOS tests" in `../AGENTS.md`. The fix workflow, launch environment, and fixtures are shared with `../KeeForgeUITests/AGENTS.md`.

## Running

```bash
xcodebuild test -project KeeForge.xcodeproj -scheme KeeForgeMac \
  -destination 'platform=macOS,arch=arm64' \
  -only-testing:KeeForgeMacUITests/MacSmokeUITests
```

- The suite runs on the Studio only when explicitly selected; Xcode Cloud does not run it. It drives real windows and takes screen and keyboard focus, so it needs an unlocked, active login session; with the screen locked it fails with "Failed to activate application (Running Background)".
- It needs Automation Mode. If `automationmodetool` (no arguments, read-only) says enabling it requires authentication, the runner prompts and, unattended, fails with "Timed out while enabling automation mode" after running zero tests. Zero tests run is a failure, not a pass.
- `MacSmokeUITests` is the required local release smoke (`prepare-release` skill).
- Split geometry autosaves into the app's defaults under `MacDatabaseWorkspace.<database UUID>`. Fixture databases get new UUIDs on each seeded launch, so no test inherits a collapsed sidebar from an earlier run; unit tests hosted by the app write none.
- `MacScreenshotAuditUITests` skips unless `TEST_RUNNER_SCREENSHOT_AUDIT=1` is set; `TEST_RUNNER_SCREENSHOT_AUDIT_DARK=1` switches its captures to dark. Both must be real environment variables on the `xcodebuild` process: a trailing `KEY=value` argument is a build-setting override that never reaches the runner, and the class skips silently.

- `MacAppStoreScreenshots` skips unless `TEST_RUNNER_APPSTORE_SCREENSHOTS=1` is set. It captures the Mac App Store screenshots from `demo.kdbx` in a 1440x900 pt database window, sized with `-ui-testing-database-window-size` because XCUITest corner drags do not resize windows on macOS 27.
- Several database windows at once (key-window routing of Find, Lock and menu commands, also with Settings key; fronting a minimized window from the Databases window; the close prompt on one window; the Window menu; the last window closing): `MacWindowLifecycleUITests`. Routing and restoration decisions stay unit-tested in `MacDatabaseCommandTargetResolverTests` and `MacWindowCoordinatorTests`.

- Entry detail and inline editor (`MacSmokeUITests`): the detail case (kitchen-sink `Multi Attachment Entry`: reveal, copy and the row's tick, Quick Look opening from a row and closing on Space), the Large Type case (button, any key, a click, View ▸ Show in Large Type and Escape), the edit case (double-click opens the editor, the title is focused, Tab reaches the username and stays there, the lists are frozen, ⌘S from the generator popover saves), the new-entry case (⌘N, title focused, the Set Up sheet ignores ⌘S and closes on Escape, ⌘S saves and selects the entry, the lists release), the custom-field protection case (header Edit, Protect Field), the generator case (Escape closes the popover alone, Use fills the field, Escape then asks before discarding, Database ▸ Password Generator and its Copy) and the close case (Lock and ⌘W with Keep Editing, then Close Database with Discard and Lock). Field order, selection concealing and the models stay in `EntryEditViewModelTests`, `KDBXCompatibilityTests`, `MacEntryDetailModelTests`, `MacEntryEditorSessionTests`, `MacWorkspacePresentationTests`, `MacLargeTypePanelControllerTests`, `MacPasswordGeneratorPanelControllerTests` and `PasswordGeneratorModelTests`. The Touch ID prompt itself, and whether its activation change closes Large Type, needs a hand check.
- Custom-icon management: `MacCustomIconManagementUITests` exercises rename, cancelled deletion, and confirmed deletion from the entry picker.
- Restore entry/group context actions and split-view refresh: the restore cases in `MacSmokeUITests`. Shared policy and persistence remain unit-tested.
- Dragging an entry onto a sidebar group: `testDraggingAnEntryOntoASidebarGroupMovesIt` (a live drag session has no unit seam; the payload and drop decision are `MacEntryDropTests` and the controller tests).
- The status card's Sync Now and its line: `MacWebDAVSmokeUITests`. Line wording, actions and gates stay in `MacDatabaseStatusTests`; notices and the native Save Conflict alert in `MacWorkspaceAlertsTests` and the controller tests.
- Entry table: the arrow-key cases (`testDownArrowMovesTheEntrySelection`, `MacListKeyboardNavigationUITests` for search; one table serves every list), double-click opening the editor, the new and renamed entry rows, and `MacSearchResultsDeleteUITests` (a row's Delete reaching the host's confirmation and the entry reaching the Recycle Bin). Mode rows, tag results, the list header, menus and their gates, native multi-select, the selection summary, code rows and their copy button stay in `MacEntryListModelTests` and `MacEntryListViewControllerTests`.
- Sidebar: `testSidebarShowsItsSectionsAndAllEntriesListsEveryGroup` (Library, Groups, Tags and Recycle Bin headers, Deleted Entries as the last row under the Recycle Bin header, All Entries listing several groups; it alone launches `kitchen-sink.kdbx`), `testDownArrowMovesTheSidebarGroupSelection` (arrows move the selection, Left and Right fold and unfold), and the restore cases (group-row menu items). Which rows appear, folding, menu gates and selection sync stay in `MacSidebarSnapshotTests` and `MacSidebarViewControllerTests`. The app staying open after its last window closes is `MacMainMenuTests`.

## Invariants

### Launch

- `-key value` argument pairs can sit on either side of the bare `-ui-testing` flag: argument-domain parsing takes the next token as a flag's value only when it does not start with `-`.
- `-ApplePersistenceIgnoreState YES` stays in the base launch. Without it state restoration can restore a session with no windows and no main window ever appears.
- Never pass `-AppleLanguages` / `-AppleLocale` on macOS: on macOS 27.2 the app then launches with no window at all (cause unknown), and every query fails as "Database list did not appear". The Mac suite relies on the session's English locale.
- To capture the app's own windows, launch with `-KeeForge.blockScreenCapture NO`, placed as above. The app excludes its windows from capture by default, so a capture is blank or shows whatever is behind the app.
- Under `-ui-testing`, revealing or copying a protected value never asks for Touch ID or the login password: `BiometricService.canAuthenticateDeviceOwner` reports no device-owner authentication, so the gate is skipped, because XCUITest cannot answer the system prompt. A reveal that shows nothing in a test is therefore never a pending prompt; look for a click that missed. A boundary test launches with `UI_TEST_DEVICE_OWNER_AUTH_PENDING=1`, which re-arms the gate with an authentication that never completes. Without it, immediate disclosure reads as a leak.
- `MacScreenshotAuditUITests` opens database windows at 1080×700 pt content, then relaunches with the 900×620 minimum for its minimum-width capture and asserts the resulting frame. Corner drags do not resize windows on macOS 27.
- Under `-ui-testing` the app restores no windows on launch and records no window topology, so one test's windows never reappear in the next (`MacWindowLaunchOptions`). Each database window it opens starts at 1080 x 700 pt content, or at the size given by `-ui-testing-database-window-size <width>x<height>` (for example `1440x900`); a malformed value is ignored. A second window cascades from the frontmost one.

### Queries

- AppKit owns the Databases window (`databases`), one window per open database (`database.<UUID>`, titled with the database name; its accessibility title adds the unlocked subtitle after an en dash), the menus (Window ▸ Databases shows the Databases window; the Window menu lists each database window by name), and the retained Settings window (`settings`). Each database window's root hosting controller remains mounted; unlocked content embeds an AppKit three-item split view: the sidebar outline, the entry table (`MacEntryListViewController`, one table for groups, Library rows, tags and search) and a detail column that hosts SwiftUI. The unlocked window's toolbar is a native `NSToolbar` (`MacWorkspaceToolbar`) with an `NSSearchToolbarItem`; the unlock screen keeps the root's bridged SwiftUI toolbar. AppKit observation sets the title.

- Sheets, alerts and dialogs raised from the sidebar or the entry table (edit, move, delete, duplicate, new group) are presented by the stable SwiftUI workspace presentation host, not by the column that asked. Keep UI coverage for keyboard and double-click browsing, a table menu reaching the host's dialog, search and Find, repeated lock/unlock width restoration, launch/enrollment presentations, and the save-conflict path. Save Conflict and the other merge and sync alerts are native `NSAlert` sheets (`MacWorkspaceAlerts`) attached to the window's topmost sheet, or the window itself, so a failed save from the inline editor shows the alert over the window with the editor still open; its Cancel (`save-conflict.cancel`) or Escape leaves the draft unsaved, and the status card then offers `save-conflict.resolve` (or Retry Save, `database.unsaved-indicator`). The split dividers are native AppKit splitters; the existing `app.splitters` query remains valid. The native toolbar exposes item identifiers on its controls: buttons still match `app.buttons[identifier]` (each item's view carries its item identifier), the search field is `app.searchFields.firstMatch`, and Command-F focuses it. The toolbar controls and search field are disabled while a save runs, so typing right after a delete or edit is lost: wait until the field is enabled. The toolbar holds the sidebar toggle, then (between tracking separators) search, New Entry (`entry-list.add-entry`) and the read-only glasses over the list, then the centred database title over the detail. Sort (`sort.menu`) is a pull-down in the list header (`entry-list.header.title`, `.subtitle`). Lock, Database Settings and Sync Now (`lock.button`, `database-details.button`, `database.cloud-sync-now`) are buttons on the sidebar's status card (`sidebar.status-card.*`), and show in the toolbar only while the sidebar is hidden. Notices (`entry-list.notices`) sit above the list header. Verify View → Show Sidebar and widths after collapse/resize and repeated lock/unlock across hosting boundaries.

- Scope queries to a window. `MacUITestCase.databasesWindow` is the Databases window, `databaseWindow(named:)` one database's window and `databaseWindow` the only one; never use `windows.firstMatch` or the largest window. The database list exists only in the Databases window, so a launcher row never proves a database locked or opened: check the database window (`waitForLockedState(in:)`, `waitForVaultToUnlock(in:)`).
- Database rows are `NSTableView` cells in `databases.list`, with `database.row` on the title text (subtitle `database-row.subtitle`, problem or last-opened line `database-row.detail`, state `database-row.open` or `database-row.locked`, `database-row.touch-id`, the Quick Launch and Read-only badges). A single click selects; double-click, Return or the row menu's Open (`database-row.open-action`) opens or fronts the database's window; there is no Open button. The brand panel holds `databases.create-new`, `databases.add-existing` and `databases.connect-server` (the File menu's commands; with two server types Connect asks with a dialog whose buttons are `database.add.webdav` and `database.add.ftp`). The bottom bar's `database.add.button` pops up the same three commands and `databases.remove` asks to remove the selection (`databases.remove.confirm`). The empty state is text only (`databases.empty.title`, `databases.empty.message`).
- Escape or Choose Different File on a database window's unlock screen closes that window and shows the Databases window. Launch presentations (transition notice, What's New) and the verification-code destination prompt (`databases.enrollment-destination.row`, `databases.enrollment-destination.cancel`) appear on the Databases window. Database menu commands are disabled while the Databases window is key; with Settings key they act on the last focused database window.
- Front a particular window with its Window-menu item (`chooseMenuItem(_:inMenu:)`, `showDatabasesWindow()`): cascaded windows overlap, so a click on the one behind can land on the one in front. Keyboard focus is app-wide, so `waitForKeyboardFocus` on a control also proves its window is key.
- Vault rows are not buttons, although the same `group.navlink` / `entry.navlink` identifiers are buttons on iOS (`../KeeForge/Views/AGENTS.md`). Never query them through `app.buttons`. Use `MacUITestCase.openGroup`, `openEntry` (which also waits for the detail title), `clickFirstRow` (returns the clicked title), or `rowQuery(identifier:)`.
- The sidebar is an AppKit outline, `window.outlines["sidebar.outline"]`. XCUITest drops a table cell's own identifier, so each row's identifier (`group.navlink`, `sidebar.collection.allEntries`, `sidebar.collection.verificationCodes`, `tag-list.row.*`) sits on its title `StaticText`, whose `value` is the title; the cell carries the title as its label. Section headers are plain `StaticText`s. Group-row menu items keep their `group-row.*` identifiers, which `NSMenuItem.identifier` exposes. A tall sidebar opens scrolled to the top. The Recycle Bin is the last section: its header, then Deleted Entries (the bin group's own `group.navlink` row), then deleted groups as sibling rows; an empty bin has no section. Each header row holds its fold chevron, a button with no identifier labelled Hide or Show, and a trailing "Show" while folded. A sidebar rebuild after a delete or restore is asynchronous: wait for the new rows before querying them.
- The entry list is an AppKit table with the same rule: each row's identifier (`entry.navlink`, or `search.entry.navlink` for search and tag results) sits on its title `StaticText`, whose `value` is the title alone. Match a row by its exact title; its username and folder are separate texts (`entry-row.folder`), so a match on them needs the row's other elements. A click selects, ⌘-click extends the selection (the detail column then shows the selection summary, `entry-selection.count`, `entry-selection.move` and `entry-selection.delete`, and Escape ends it), double-click and Return open the editor. Verification Codes rows keep `entry.navlink`; the code is the `verification-code-row.copy` button, which copies it. A drag starts from a row title with `click(forDuration:thenDragTo:)` and drops on a sidebar title.
- `waitForVaultToUnlock` waits for a `group.navlink` row in the window (toolbar buttons can collapse into the overflow and prove nothing); `waitForLockedState` needs the unlock field with neither those rows nor the outline, which is meaningful only because unlock detection finds the same rows.
- Most SwiftUI `Text` reports through the AppKit `value` attribute with an empty `label`. Read text with `displayText(of:)` and wait with `waitForDisplayText(_:identifier:)`, which re-queries every pass: reading a property from an element a rebuilding view has replaced fails the test.
- Table rows scrolled out of view still match. Click only a hittable match with a real height, as the row helpers do.
- Match a context-menu item as an enabled, hittable `menuItems` element, never `firstMatch` on its title. The menu bar holds disabled items with the same titles; `firstMatch` picks one, clicks nothing, and leaves the context menu open and the window modal.
- A SwiftUI `Toggle` in a form is a switch, not a checkbox: query `app.switches` and read its state as a number (`value as? Int`), not the string iOS reports.
- The detail column hosts the entry detail (`entry-detail.title`, Edit `entry-detail.edit` in its header, footer link `entry-detail.history`, a `links` element) and, in its place, the inline editor (`entry-edit.*`; Cancel `entry-edit.cancel` takes Escape, `entry-edit.save` reads Save or Create, and File ▸ Save, ⌘S, saves it). While the editor is open the sidebar, the entry table, search and New Entry are disabled, as during a save: wait for the search field to be enabled after Save or Cancel. Its alerts (Discard Changes, the lock prompt's Keep Editing / Discard and Lock) are window sheets. A new entry's password field is plain text (`textFields`); an existing entry's is secure until revealed. Protect Field (`entry-edit.custom-field.protection.N`) is a button whose `isSelected` is the protection. The Set Up sheet's link field is a text view (`textViews["entry-edit.totp.link-field"]`). The generator popover is `app.popovers`, its suggestion `password-generator.password` (label "Suggested Password", the text in `value`).
- The Large Type panel (`large-type.panel`) and the Password Generator panel (`password-generator.panel`) are separate windows: query them with `app.descendants(matching: .any).matching(identifier:)`. Quick Look is the system panel with no identifier; a change in the count of `app.windows` and `app.dialogs` shows it. Never read the preview's temporary file from the runner: it lives in the app's container, and touching another app's container raises a privacy prompt that stalls an unattended run.
- Scroll the scroll view that contains the target (`scrollIntoView(_:in:)`). `app.scrollViews.firstMatch` is usually the sidebar or a list, not the editor or entry detail, and scrolling it leaves the target where it was.
- A control touching the window's bottom edge reports hittable, but a click there misses it. Scroll it clear of the edge first.
- XCUITest drags do not move split-view dividers on macOS 27, so resizing a column is a manual check. Unit tests cover native split-item constraints and collapse; autosave restoration requires the repeated-lock/unlock UI test and manual divider resizing.
- Toolbar buttons, `lock.button` included, can collapse into the "more toolbar items" overflow, where they are menu items matched by label. Use `clickToolbarButton(identifier:overflowLabel:)`, and detect the unlocked state from vault rows as `waitForVaultToUnlock` does.
- Settings can never become main, so XCUITest reports it as a dialog: query it as `MacUITestCase.settingsWindow` (`app.dialogs["settings"]`), never `app.windows`.
- The retained AppKit Settings window reopens on the tab used last in this process; a fresh root starts on Security. Select the tab with `selectSettingsTab(named:)`; the `settings.tab.*` identifiers sit on tab content, not on the switching control.
- Closing a database window locks and retires its session (`MacWindowCloseGuard`), even with other windows open, and the app keeps running with no window. A test pressing Command-W in a database window must expect the window to close and its database to lock; the Databases window reopens it in a new, locked window. Removing a database from the list closes its window.

### Screenshot audit

- Captures come from each window's own content through ScreenCaptureKit. `XCUIElement.screenshot()` and `XCUIApplication.screenshot()` capture the screen region and return whatever is in front.
- The runner (`KeeForgeMacUITests-Runner`) needs Screen Recording permission, under System Settings > Privacy & Security > Screen & System Audio Recording.
- A capture that cannot be taken is listed in the `00-skipped-captures` attachment instead of attaching the wrong pixels. A short export is a harness problem, not a missing screen.
- Captures are forced light or dark through `-KeeForge.appearanceMode`; the host appearance does not decide.
- `testCaptureScreens` also captures a selected Library row (`03b`), Verification Codes with live codes (`03c`), Passkeys (`03e`, its empty state), an empty group (`03d`), a ⌘-click multiple selection with the detail summary (`04b`), an entry's and a group's row menu (`08h`, `08d`; ScreenCaptureKit finds no window record for a menu, so they are listed as skipped), Deleted Entries after those deletes (`08e`), a folded Library section (`08g`), the hidden sidebar (`08f`), the inline editor on Work/Email (`08`) with its generator popover (`08k`), a new entry (`08i`) with the Set Up sheet (`08c`) and the discard prompt (`08j`), the Password Generator panel (`08l`), and relaunches read-only (`UI_TEST_DATABASE_READ_ONLY`) for the read-only detail (`10b`) and, at the minimum size, `10-minimum-width`, then Verification Codes at that width (`10a`). `testCaptureEntryVariants` opens kitchen-sink as Personal for the attachments (`05a`), a protected custom field (`05a2`), Large Type (`05b`), the copy tick (`05c`), tags (`05d`) and History with differences on `Round Trip/Controlled Unknowns` (`08b`), then relaunches writable at the minimum size for the detail (`10c`) and the editor (`10d`). Quick Look is a system panel and is not captured. It ends by relaunching writable with `UI_TEST_LOCAL_SAVE_CONFLICT_COUNT=1` and deleting a group: `04a-save-conflict-alert` is the native alert, Cancel leaves `04c-status-card-unsaved`, and the card's action saves again (a quit with an unsaved draft would prompt and stall the teardown). `testCaptureServerDatabasesInTheDatabasesWindow` adds a mock WebDAV server whose uploads need write access: opening Family and deleting a group shows the reconnect notice above the list and the card's problem line (`13-notice-reconnect`), then ⌘W and Don't Save close it. `UI_TEST_HIDE_SEARCH_RESULTS_COUNT=1` keeps the `results:N` test overlay out of them, while other suites still read `search.results.count`.
