# Test Support

Shared test infrastructure: fixtures, fakes, spies, and assertion helpers. Nothing here declares a test class — suites live one level up in `../`.

## Helpers

- `TestDatabaseSupport.swift` builds fixture URLs, supports fixture subdirectories, reads non-database fixture bytes (`fixtureData(named:extension:bundle:)`, for key files), and creates bookmark-backed `DatabaseReference` values for tests.
- `FakeCredentialIdentityStore.swift` is the lock-guarded in-memory `CredentialIdentityStoreProviding` fake; install it via `CredentialIdentityStoreManager.storeProviderOverride` and drive assertions through its `stored`/`calls`/`onMutation`/`onEnumerate` surface. It also owns the process-wide credential identity store test reset and mutation-barrier invariant used by the affected AutoFill and database suites.
- `CredentialProviderPresentingSpy.swift` is the shared `CredentialProviderPresenting` recording spy used by the coordinator, save, picker-creation, and registration suites; it records every presentation/completion call, the last `cancelledError`, and the ordered `cancelledErrorCodes` history.
- `KDBXTreeAssertions.swift` holds the `KDBXTestFixture` catalog: every bundled database a unit test opens is described exactly once there (name, subdirectory, password, key file), and the descriptor is also the only way to open one — `url(in:)`, `data(in:)`, `keyFileData(in:)`, `compositeKey(in:)`, and `parse(in:sessionKey:)`, which returns the tree, meta, header, and composite key. Add a named descriptor there rather than inlining a `KDBXTestFixture(...)` literal, a `Bundle.url(forResource:)` lookup, or a per-suite loader in a suite; the parse/write suites lost coverage that way before. It also holds the canonical `assertTreesEqual`/`assertGroupsEqual`/`assertEntriesEqual`/`assertTOTPConfigsEqual`/`normalizedOpaqueXML` comparators used by `KDBXRoundTripTests.swift` (XML layer) and `KDBXWriterTests.swift` (container layer). Add new "did this field survive a save" checks here so both layers gain them together; do not re-add per-suite copies, which is how the writer suite previously lost `searchingEnabled`/`expires`/`expiryTime` coverage.
- `KDFPolicyTestSupport.swift` adds test-target overloads of `KDBXParser` parse/derive, `KDBXWriter.write`, and the saver `save` methods that omit `kdfPolicy:` and forward `.mainApp`; tests that exercise policy selection (`KDFExecutionPolicyTests.swift`, `CredentialProviderSaveTests.swift`) pass the policy explicitly.
- `KDBXCompatibilitySupport.swift` is the shared compatibility harness: fixtures (a `Fixture` is an artifact ID wrapped around either a `KDBXTestFixture` descriptor or a generated database, and takes its password and key file from that descriptor), scenarios, `CompatibilitySnapshot`, the artifact set (`artifactDescriptors`), the external-opener expectation tables, and `ArtifactCollector`. A `Fixture.id` is an artifact ID consumed by the gate's manifests and by this suite's allow-lists, independent of the bundled file it reads: `aes-baseline` reads `test.kdbx` and `password-keyfile` reads `demo-keyfile.kdbx`/`.key`, since no fixture is kept twice on disk. Keep the IDs stable when retargeting a fixture's source. Keep the all-edit compatibility matrix there and in `KDBXCompatibilityTests.swift`; do not duplicate it in writer, draft, or saver tests.
- Shared databases and key files are documented in `../../TestFixtures/README.md`.
