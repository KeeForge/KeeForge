# KeeForgeMac

**Scope:** the native macOS app's AppKit shell in `App/`: startup, the app delegate, the window coordinator, database and Databases windows, menus, the Settings window, the split workspace's AppKit controllers and toolbar, sheet and alert presenters, and the SwiftUI form content those presenters host. Distribution channels, entitlements and `Info.plist` sync are in `README.md`; the security model is in `SECURITY.md`. Shared iOS/Mac app rules are in `../KeeForge/App/AGENTS.md`.

## Where Mac code goes

- AppKit controllers, presenters and panels, and the SwiftUI content of a sheet or panel that one of them hosts (new database, master key, group editor, …): `App/` here.
- SwiftUI screens hosted in a Mac window's content (detail column, inline editor, history, locked pages, Settings tabs, quick search): `../KeeForge/Views/**/Mac/`, or a `Mac*` file at a Views folder root, wrapped in `#if os(macOS)`.
- Mac SwiftUI glue that is not a screen (workspace host, column hosts, auto-unlock observer, sheet cancellation): `../KeeForge/App/Mac*`.
- `@Observable` models: `../KeeForge/ViewModels/Mac*`, free of AppKit and SwiftUI, tested in `../KeeForgeTests/`.
- Services: `../KeeForge/Services/AppSupport/Mac*` and `../KeeForge/Services/SSHAgent/`.
- The `Mac` prefix means Mac-only, except `MacAppSuggestionService` and `MacAppSuggestionBanner`, the iOS "get the Mac app" banner.

## Ownership

- `AppDelegate` owns the session store, the database list, `MacDatabaseWindowRegistry`, appearance, and the SSH agent and quick-access controllers, and installs the list hooks when it builds the shared models. No Mac code reads or writes `activeSession`/`activeSessionID`.
- `MacWindowCoordinator` owns the Databases window and one `DatabaseWindowController` per open database, keyed by database UUID, and is the only writer of their frames and the restoration topology.
- `MacWindowCoordinator` applies `MacApplicationRouting` (launch presentations before any open, queued URL and Quick Launch opens, duplicate fronting, Dock reopen) and owns one app-level `TOTPEnrollmentCoordinator`, bound to the database window targeted when a link arrives or to the database chosen in the Databases window.
- `DatabaseWindowController` holds its session directly for its whole life, with the window's `MacUnlockFormModel`, `MacFilePanels`, `MacWorkspaceSheets`, `MacWorkspaceAlerts` and `MacAttachmentPreviewController`. `MacWindowWorkspace` owns the split controller and toolbar for one unlocked lifetime.
- `MacDatabaseRootView` (`App/`) shows the locked page `MacDatabaseOpenPage` names (unlock form, opening, recovery, unavailable; `../KeeForge/Views/Unlock/AGENTS.md`) or embeds `MacDatabaseWorkspaceView`, which embeds the window-owned `MacWorkspaceSplitViewController` through a representable. Its sidebar and entries items are the AppKit `MacSidebarViewController` and `MacEntryListViewController` (`App/`); the detail item hosts one SwiftUI column. While the split is shown the window's toolbar is the native `MacWorkspaceToolbar` (`App/`); a locked window has no toolbar, only its name in the titlebar. The root host never bridges SwiftUI toolbars. Column hosts never bridge. The detail header's Edit goes through the shared presentation object.
- The Mac `MainMenu` builds the AppKit menu. Nil-target actions reach `AppDelegate` for app actions and a `DatabaseWindowController` for database actions. `MacDatabaseCommandTargetResolver` picks that controller for validation and again at dispatch: the key database window or a key sheet's parent, else the main database window while Settings or a panel is key, and none while the Databases window is key; `AppDelegate.supplementalTarget` and each controller's `isCommandTarget` gate both use it. New Database, Open Database File and Connect to Server are launcher operations that ignore session state; the launcher's brand panel sends the same commands. Lock All Databases is an app command: `MacWindowCoordinator` sends each unlocked window's session the same lock request as Lock. `DatabaseCommands` owns enablement and actions; presentation commands only raise workspace request counters. Find is a window concern: the controller focuses its toolbar's search field directly.
- `MacLockMonitor` owns app-wide lock triggers on macOS; `MacWindowCloseGuard` settles each registered window's unsaved work and locks only its session on committed close (`../KeeForge/Services/AppSupport/`). `AppDelegate` owns `MacDatabaseWindowRegistry`; the coordinator registers each database window once before showing it and unregisters it on committed close, which also retires that session and releases the controller.

## Invariants

### Windows, launch and quit

- Incoming Mac URLs queue in `MacWindowCoordinator` until startup, and database opens queue in `MacApplicationRouting` until the launch presentations are dismissed. The transition notice and What's New are presented once per launch from the Databases window; the notice suppresses What's New and Quick Launch for that launch.
- Mac window restoration runs once, after the launch presentations and before queued or Quick Launch opens (`MacApplicationRouting.Effect.restoreWindows`). It recreates windows only with new locked sessions, registered as restoring so `admitsAutomaticUnlock` refuses until the user clicks or types in the window (`MacLockMonitor.onUserActivity`) or opens that database explicitly; becoming key during launch does not count. Restoration takes precedence over Quick Launch, and a launch URL for a restored database fronts its window. `MacWindowCoordinator` is the only writer of the topology and of top-level frames, and records nothing until restoration has run.
- Mac quit settles each database window's unsaved write before termination (`MacWindowCoordinator.requestTermination`): a window whose editor holds unsaved fields is asked first, through the editor's own lock prompt (Save and Lock, Discard and Lock, Keep Editing), and the quit goes on once that window has locked; Keep Editing cancels it. For the remaining windows every answer is collected before anything is written, and any cancel or failed save cancels the quit with those sessions untouched. Only a quit that proceeds records the pre-quit topology and freezes the record. A quit that goes ahead also removes attachment previews and clears the clipboard copy KeeForge still owns (`ClipboardService.clearOwnedContents()`); it locks no session. A cancelled quit changes nothing. Every `NSApplication.terminate`, logout and restart reaches `applicationShouldTerminate`; only a force quit, crash or kill skips it (`SECURITY.md`).
- The database window's minimum height (620) must stay clear of `MacSheetMetrics.maxHeight` (560, `../KeeForge/Extensions/PlatformCompat.swift`): a sheet is anchored under the toolbar. Raise them together. The shorter Databases window (780 x 440 minimum) instead grows to fit each sheet it begins (`DatabasesWindow`).
- List removal force-retires the session and the coordinator closes its window.

### Workspace

- Native split items own widths and collapse state through `NSSplitView` autosave, one name per database (`MacWindowRestorationStore.splitViewAutosaveName(for:)`). Never retain database contents to preserve layout; release the controller on lock or replacement.
- `DatabaseWindowController` observes its session's unlocked state, database title, and group/tag/collection/search subtitle using `MacObservation`. `MacWindowWorkspace` owns the native controller and toolbar for that unlocked lifetime; the window controller installs that toolbar on unlock and removes it on lock. It also owns the window's `MacUnlockFormModel` and its `MacFilePanels`, and clears the form on unlock, on every new lock cycle (including Cancel while opening) and on invalidate. The root hosting controller remains mounted across swaps to preserve enrollment sheets and the biometric observer; only its unlocked content embeds the split. Never make the window key or change first responder during a content update.
- `MacObservation` tracks reads separately from effects, re-arms on the main actor after mutation, and invalidates queued callbacks on cancellation/replacement. Capture owners weakly in its read/effect closures. The SwiftUI detail host observes saving disablement and the accent tint itself because SwiftUI environments do not cross a representable into independent hosting roots. The AppKit sidebar and entry list disable their views while saving or while the inline editor is open (`MacWorkspacePresentation.freezesWorkspace`). Light/Dark is app-wide: `MacAppAppearance` sets `NSApp.appearance` from the setting, and no window, sheet or hosting root pins its own.
- The sidebar is a source-list `NSOutlineView` and the entries column a view-based inset `NSTableView`, so arrow keys, type-select, extended selection, and the focus ring come from AppKit. Each row's identifier sits on its title text, because XCUITest drops a table cell's own identifier; Mac UI tests match rows with `descendants(matching: .any)` (`../KeeForge/Views/AGENTS.md`, `../KeeForgeMacUITests/AGENTS.md`).
- The entry list renders `MacEntryListSnapshot` (`../KeeForge/ViewModels/MacEntryListModel.swift`) through one `MacObservation`. Edits, renames, creation, deletion and resorting remove, move and insert rows in place and reconfigure existing cells, so row views, selection and scroll survive; only switching to another list (a group, tag or collection, or into or out of search) reloads the table. Usernames are resolved when a cell is configured, so rows never drawn never resolve field references.
- Entry selection maps both ways through `MacEntryListSelection`: one row is `selectedEntryID`; two or more are `entrySelection` (movable rows only, one row in a read-only database), and a pick does not outlive its row: `dropHiddenPicks` drops picks the list stops showing (sidebar, search, merge) when the list applies a change and again before Delete or Move acts, so the header count, summary, confirmation and action agree. Escape ends it. While it lasts, the detail column shows `MacEntrySelectionSummary` with Move to Group… and Delete, and Delete (menu bar, row menu, summary) recycles the picks through `deletableSelection`'s `.entries` and `PendingDeletion.entries`, the same confirmation host and save as a single delete. Return, Enter and double-click open the entry through `requestEntryEdit()`; bare Delete, Space and ⌘C do nothing.
- Verification Codes rows show the live code from `MacVerificationCodeClock`. The table owns one timer, running only while that list is showing, the view has appeared and the session is unlocked; a tick redraws visible rows only, and every stop resets the clock's cache. The copy button goes through `DatabaseCommands.copyVerificationCode(entryID:)` only.
- The entry row menu comes from `EntryRowActions` (bulk: Move to Group… and Delete). Its Copy Password goes through `DatabaseCommands.copyPassword(entryID:currentSession:)` with the window controller's `isCurrent` recheck; username copies through `DatabaseCommands.copyUsername(entryID:currentSession:)`, which takes the same gate when the username's references reach a protected value. Row-menu selectors must not reuse a main-menu command's selector, or the table's controller intercepts the menu-bar command. A duplicate made from search or a tag selects the copy in place (`MacWorkspacePresentation.selectsCreatedEntryInPlace`); elsewhere the host reveals it.
- Mac sidebar navigation is selection on `DatabaseViewModel.workspace`, never a pushed stack. `GroupListView` never renders on macOS.
- Sheets and the native Move/Restore picker belong to the window controller’s `MacWorkspaceSheets`; native confirmations and errors belong to `MacWorkspaceAlerts`, never a row or column. The presentation object belongs to its `DatabaseWindowController` and resets on lock or window invalidation (sidebar expansion excepted), releasing forms and invalidating old cloud-reconnect completions. Both presenters reject old lock-cycle callbacks and end attached sheets top-down; the shell cancels registered hosted work synchronously without cancelling database writes. Initial focus belongs to the shell’s begin operation, never to SwiftUI updates.
- Delete, save-error and dirty-draft lock prompts use `NSAlert` sheets through `MacWorkspaceAlerts`. Sheet requests wait until the preceding sheet has detached. Master-key, encryption and import sheets register their cancel paths with `MacSheetCancellationScope`; it ends them even if SwiftUI disappearance is delayed.
- Two `NSTrackingSeparatorToolbarItem`s on the split's dividers put search and New Entry over the entry list, and the database's items over the detail; Edit is in the detail's header. No item is navigational, and the window hides its title while the workspace toolbar is installed, because the list header shows it.
- The list header (title, count line, Sort) and footer hint come from `MacEntryListSnapshot.header` and `.footer`; Sort lives only there and in View ▸ Sort By.
- `MacWorkspaceToolbar` item identifiers are the accessibility identifiers the UI tests query; each item's view carries the same identifier. The search item and `DatabaseViewModel.searchText` are bound both ways; enablement comes from `DatabaseCommands` where a rule exists, and every item is disabled while saving; search and New Entry are also disabled while the inline editor is open, and Lock never is. File ▸ Save saves the open inline editor (`MacWorkspaceCommands.save`); the window controller closes the editor when its session locks.

### Sheets and alerts

- A native sheet's form is SwiftUI content in a `MacFormSheetController` shell, presented by `MacWorkspaceSheets` (database windows), `MacDatabasesSheets` (the Databases window), `MacDatabaseSettingsLauncherPresenter` or `MacServerReconnectSheet`; the shell sets its size under `MacSheetMetrics.maxHeight` and initial focus once. A few hosted views still present SwiftUI sheets of their own (enrollment and launch notices, the editor's verification-code setup, the detail's history, the icon manager).
- The Databases window's `MacDatabasesSheets` owns native creation, connect and remote browsing; its close handler ends them and clears the launcher's request. Reconnect is `MacServerReconnectSheet` on each database window, including the locked recovery page, cleared through the existing credential prompt on lock and controller invalidation. Tests: `MacDatabasesSheetsTests`; shell async default-action semantics: `MacFormSheetControllerTests`.
- The Databases window's `MacDatabasesAlerts` takes the launcher's Remove, Can’t Remove, Rename, Discard Pending Upload, selection and pending-upload requests off the models and asks with `NSAlert` sheets through one `MacAlertQueue`; its key-file request uses `MacFilePanels`. A locked window's Remove from List asks through its controller's own queue. A queue shows one alert at a time, holds an alert raised while another is up or detaching instead of dropping it, runs an answer only once its sheet has detached, and ends unanswered with every queued request on window close (and controller invalidation). Removal still rechecks unsaved work after confirmation; the database window path also rechecks controller identity. Tests: `MacAlertQueueTests`, `DatabaseWindowControllerTests.testRemoveFromListAlertsQueueInTheWindowAndEndOnCloseAndInvalidation`, `MacWindowCoordinatorTests`.

### Menus and Settings

- `SettingsWindowController` retains the Settings window (`settings`). It cannot become main, so database commands keep targeting the database window behind it, and it reads no window's session; the SSH Agent tab shows the database picked in its menu, or the first unlocked one until the user picks. Settings buttons send `showSettings:` through the responder chain. Mac activation notifications replace scene-phase reads for enrollment expiry and AutoFill status.
- The AppKit File menu includes Close Window (Cmd-W). The macOS lock guarantee and `MacWindowCloseGuard` assume that shortcut exists.
- Every item is disabled when it cannot apply (locked, read-only, no selection). Enablement for Edit and Delete comes from the same view-model properties the action uses.
- Copy Password goes through `EntrySecretAction` and revalidates after authentication that the originating window still owns the same session (the active session on iOS).

- Local-save recovery is available from Database Settings even for a locked database. Both security sheets finish uncertain writes with Done and never repeat the completed operation. It uses the existing launcher sheet owner, respects an in-flight creation/connect request and closes with Done. `MacDatabasesSheetsTests` covers the empty-list entry and busy-sheet guard.
